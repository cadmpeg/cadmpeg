Record offsets, field widths, and endianness are also maintained as a machine-checked table in [`docs/layouts/iges.md`](../layouts/iges.md), generated from `docs/layouts/iges.toml`. ## Physical representation

The representation flag is in the first 80 bytes. A `C` in byte 73 identifies Compressed ASCII. The other bytes of its flag record are printable ASCII. An `S` in byte 73 identifies Fixed ASCII.

The Binary representation starts with one 80-byte Binary Flag Section. Byte 1 is ASCII `B`. Bytes 2 through 5 are the big-endian unsigned 32-bit value `75`, which is the count of the remaining flag bytes. Bytes 6 through 11 are the one-byte bit lengths `Is`, `Id`, `NXs`, `NFs`, `NXd`, and `NFd`. Bytes 12, 17, 22, 27, 32, and 37 are ASCII `B`, `S`, `G`, `D`, `P`, and `T`. Each letter is followed by a big-endian unsigned 32-bit displacement for that section. Bytes 42 through 72 are unassigned. Byte 73 is ASCII `B`, bytes 74 through 79 are ASCII blanks or zeroes, and byte 80 is ASCII `1`. The Binary Flag Section contains no control bytes.

The Fixed ASCII representation is an ordered sequence of physical lines. A canonical line contains an 80-byte card followed by a line ending. A conformant line has exactly 80 payload bytes; the final line may end at file end. Card bytes 1 through 72 are section data. Byte 73 is the section marker. Bytes 74 through 80 are the right-aligned decimal sequence field. Parameter Data cards instead use bytes 65 through 72 for the right-aligned Directory Entry back-pointer, byte 73 for the `P` marker, and bytes 74 through 80 for the Parameter Data sequence. Before the Terminate card, every physical line is one 80-byte card with a recognized section marker and a valid positive sequence. A short, blank, or other unsequenced line before Terminate is malformed and is not an opaque record. A recognized section marker with an invalid sequence is also malformed. A physical line with more than 80 payload bytes is malformed; bytes beyond column 80 do not form another card. The Terminate card is the last sequenced line, so bytes after its 80-byte card and before the next line boundary are not an unsequenced line and are malformed. Unsequenced lines may follow the Terminate line and are ignored by conforming postprocessors. The decoder has a CADIR recovery for a same-line suffix: when the first 80 bytes are a valid Terminate card, it retains the card and the suffix as a separate opaque `post-terminate` physical record, with no section or sequence semantics assigned to the suffix. This follows the fixed-line and post-Terminate rules in [IGES 5.3 §2.2](https://paulbourke.net/dataformats/iges/IGES.pdf) and [§2.2.4.6](https://paulbourke.net/dataformats/iges/IGES.pdf).

Byte positions are one-based in this specification. Source spans use zero-based half-open byte ranges. Parsing records the card payload and line ending as disjoint source spans before interpreting fields. A short card, a noncanonical line ending, and bytes after the Terminate card remain separate physical records with their original spans.

The canonical section order is Start (`S`), Global (`G`), Directory Entry (`D`), Parameter Data (`P`), and Terminate (`T`). Section sequences are positive decimal integers starting at one and increasing by one within each section. A Directory Entry occupies two consecutive `D` cards. Its first card has an odd sequence and its second card has the following even sequence. Directory pointers refer to the odd Directory Entry sequence. Zero is a null pointer where the owning field permits null.

The Terminate data area contains four eight-byte fields: `S` plus the seven-digit Start count, `G` plus the seven-digit Global count, `D` plus the seven-digit Directory Entry card count, and `P` plus the seven-digit Parameter Data card count. The remaining data area is blank.

## Global section

The Global field categories and empty-field defaulting rule follow [IGES 5.3 §2.2.1](https://paulbourke.net/dataformats/iges/IGES.pdf). The Global data-type rules follow [§2.2.2](https://paulbourke.net/dataformats/iges/IGES.pdf). The field definitions and default values are in [§§2.2.4.3.1–2.2.4.3.26](https://paulbourke.net/dataformats/iges/IGES.pdf).

The Global data stream is the concatenation of bytes 1 through 72 from its cards. Its first value defines the parameter delimiter and its second value defines the record delimiter. Each is a one-character Hollerith string. Omitted first and second values select comma and semicolon respectively.

A Hollerith value is an unsigned decimal byte count, the byte `H` or `h`, and exactly that many following bytes. Delimiters inside the counted payload are data. The count and payload may cross card boundaries. Integer values are signed decimal integers. Real values accept a decimal point and an exponent introduced by `E`, `e`, `D`, or `d`. An empty or blank-only field between delimiters is omitted. The record delimiter terminates the Global record.

An IGES real is a sending-system approximation. A `D` or `d` exponent selects the Global double-precision significance; every other real spelling selects the Global single-precision significance. For a nonzero real value `x` with `p` declared significant digits, its representation uncertainty is `0.5 × 10^(floor(log10(abs(x))) - p + 1)`. Zero and integer tokens have zero representation uncertainty. Two redundant numeric fields agree when their absolute difference is no greater than the sum of their representation uncertainties.

Global fields are ordered as the twenty-six fields in Table 1. Fields 1 and 2 are required-default delimiter fields. Fields 3 through 11 and 17 through 19 are required-no-default fields. Fields 12 through 16 and 20 through 26 are required-default fields. The defaults are: field 1 comma; field 2 semicolon; field 12 the value of field 3; field 13 `1.0`; field 14 inches (`1`); field 15 the name for the default inches selection; field 16 `1`; field 20 `0.0`, which means that the maximum coordinate is unspecified; fields 21 and 22 NULL; field 23 `3`; field 24 `0`; and fields 25 and 26 NULL. Field 15 is ignored when it is inconsistent with field 14 unless field 14 is `3`. An omitted or blank field selects its defined default. A supplied value must have its declared lexical type and valid numeric or date syntax; malformed supplied data does not select a default. The single-precision and double-precision significance fields are positive integers representable as `u32`. The model scale and maximum line width are finite and positive. The line-weight gradation count is greater than zero. Field 19 is required-no-default and defines the smallest discernible model-space distance under [IGES 5.3 §2.2.4.3.19](https://paulbourke.net/dataformats/iges/IGES.pdf). The decoder requires its supplied value to be finite and nonnegative; this is the CADIR admission rule. A supplied zero is retained as zero and makes field-19 distance comparisons exact. Face-local carrier agreement uses this declared value; face-local sewing also applies the coordinate-quantum rule stated in the face topology section. Other consumers apply the separate computational floors stated below. The maximum coordinate is finite and nonnegative. Field 18 and a supplied field 25 use `15HYYYYMMDD.HHNNSS` or `13HYYMMDD.HHNNSS`, with the ranges stated by the format. A version flag below `1` is assigned `3`; a version flag above `11` is assigned `11`.

The reader ignores ASCII space padding outside counted Hollerith payloads when it reconstructs Global fields from fixed cards. Spaces inside a counted payload remain data. For reader compatibility, an omitted sender-product field is retained as NULL; a supplied sender-product field remains required to be a valid Hollerith string. Semantic writing always emits the sender-product field and does not use this reader extension.
Semantic output uses one fixed Global profile. Fields 3 and 5 identify `cadmpeg`; field 4 is `generated.igs`; field 6 is `0.1`; fields 7 through 11 declare `32`, `38`, `6`, `308`, and `17`; field 12 is the empty receiver-product string; fields 13 through 17 declare model scale `1.0`, millimetres (`2`, `MM`), one line-weight gradation, and maximum line width `1.0`; fields 21 and 22 use the generated-file author marker `author` and organization `cadmpeg`; field 24 is `0`; and fields 25 and 26 are empty. Field 18 is the current UTC generation time. Field 19 is the generated topology-resolution bound. Field 20 is the largest absolute coordinate in the emitted Type 110, Type 116, and Type 502 coordinate lists, or zero when those lists are absent. Field 23 is the selected target version flag. These values are output-profile metadata; they do not replace source metadata during decode.

Units flags `1` through `11` select inches, millimetres, other named units, feet, miles, metres, kilometres, mils, microns, centimetres, and microinches. Field 14 controls the units unless its value is `3`; field 15 is redundant for every other flag and is retained for human readability. For flags other than `3`, the standard field-15 payloads are `IN` or `INCH`, `MM`, `FT`, `MI`, `M`, `KM`, `MIL`, `UM`, `CM`, and `UIN`, with exact Hollerith bytes. When field 14 is `3`, field 15 is a nonempty unit-name string that shall conform to [MIL-STD-12D](https://quicksearch.dla.mil/qsDocDetails.aspx?ident_number=35330) or [ANSI/IEEE 260-1978](https://standards.ieee.org/ieee/260/440). IEEE 260-1978 requires unit-symbol case to be significant and permits SI prefixes to combine with the metre symbol. For ASCII flag-3 length projection, the exact delegated symbols and millimetre factors are `A` (0.0000001), `in` (25.4), `ft` (304.8), `mi` (1609344), `mil` (0.0254), `uin` (0.0000254), `yd` (914.4), `nmi` (1852000), `dam` (10000), `hm` (100000), `km` (1000000), `Mm` (1000000000), `Gm` (1000000000000), `Tm` (1000000000000000), `Pm` (1000000000000000000), `Em` (1000000000000000000000), `m` (1000), `dm` (100), `cm` (10), `mm` (1), `um` (0.001), `nm` (0.000001), `pm` (0.000000001), `fm` (0.000000000001), and `am` (0.000000000000001). The delegated symbols are exact ASCII bytes; ordinary uppercase aliases such as `MM` and `NMI` are not equivalent. The Hollerith payload remains exact, including spaces and letter case. This is a CADIR decision: retain every admitted printable name in Global metadata and source fidelity, but project length-valued data to neutral IR only when the codec has a proven millimetre factor; otherwise refuse semantic projection before geometry. Type 316 does not provide that factor: under [IGES 5.3 §4.77](https://paulbourke.net/dataformats/iges/IGES.pdf), its scale applies only to the real data of each entity that owns its property pointer. Length-valued fields are converted from the declared units and model scale only when projected to neutral IR. Native values remain unchanged. The specification version field is `9` for IGES 5.1, `10` for IGES 5.2, and `11` for IGES 5.3.

The units flag and units-name values are defined by [IGES 5.3 §§2.2.4.3.14–2.2.4.3.15](https://paulbourke.net/dataformats/iges/IGES.pdf). The listed ordinary-flag Hollerith payload and byte case are significant, and padding is data. The flag-3 name is delegated to the referenced unit-symbol standards; it is compared only with the exact delegated length-symbol table above and is not normalized by the decoder.

Semantic target profiles are explicit. IGES 5.1, 5.2, and 5.3 admit the complete emitted Type/form envelope: Types 100, 102, 104 Forms 0, 2, and 3, 110, 116, 123, 124, 126, 128, 141, 142, 143, 144, 186, 190, 192, 194, 196, 198, and Types 502, 504, 508, 510, and 514 Form 1. Only IGES 5.3 admits Shell Entity Type 514 Form 2. Selecting 5.1 or 5.2 for a model that requires an open shell refuses the write before any bytes are produced. An entity outside this envelope also refuses the write before any bytes are produced. Generated Global field 19 is at least the shared neutral coincidence floor, every finite positive edge or vertex topology tolerance used by the writer, and the writer's scale-relative endpoint admission bound. The pcurve endpoint check and the generated field use the same effective topology tolerance.

Semantic output maps the neutral analytic surface family directly: Plane to Type 190 Form 1, circular cylinder to Type 192 Form 1, circular cone to Type 194 Form 1, sphere to Type 196 Form 1, and torus to Type 198 Form 1. A circular cylinder, circular cone, sphere, or torus must support B-rep topology and uses physically dependent Point Type 116 and Direction Type 123 entities. These analytic entities retain the exact unbounded carrier and its parameter frame without rational conversion. Types 192 through 198 are B-rep surface entities and are not emitted as standalone or trimmed-surface carriers. Type 108 and Type 120 do not express these analytic carriers, and Type 128 requires a finite parameterized patch. A non-B-rep analytic surface therefore refuses before bytes are produced. This refusal has no loss note because no output representation is selected.

Generated analytic frames accept normalized axis dot-product residuals through `1e-6`. The writer keeps the primary axis, removes its component from the reference axis, normalizes the repaired reference, and derives the third axis by a right-handed cross product. A placement's supplied third axis must have the same handedness and a cross-product residual through `1e-6`. Larger skew is malformed and is refused before output. The repair bound is a writer convention for finite-precision neutral frames, not an IGES file tolerance.

The format-authoritative numeric rules are Global real-token representation intervals, Global minimum resolution, the Global single-precision coordinate quantum, and the interval and domain invariants stated for each entity. Other numeric thresholds are codec policies. Decoder policies use machine-epsilon geometry classification, `10^-12` conic standard-position and NURBS-plane normal gates, scale-relative `10^-10` frame, carrier, endpoint, offset, spline, and conic-placement comparisons, and `2π × 10^-12` angular comparison. Writer policies use `1e-6` frame repair, `1e-10` NURBS closedness and same-value comparison, `1e-8` scale-relative endpoint admission, and the `1e-10` and `1e-12` scale-relative NURBS-plane construction gates. These policies accept or refuse a neutral projection or semantic write; they do not replace a Global tolerance, change an entity field, or claim authority as an IGES tolerance. Omitted parameter values use only the defaults stated by the corresponding entity definition, and malformed supplied values never select a default.

Global strings are unlimited-length Hollerith strings of printable ASCII bytes (`0x20` through `0x7E`). Blanks, parameter delimiters, and record delimiters are ordinary string data. ASCII controls (`0x00` through `0x1F` and `0x7F`) and bytes above `0x7F` are forbidden by [IGES 5.3 §2.2.2.3](https://paulbourke.net/dataformats/iges/IGES.pdf). The decoder rejects a Global Hollerith payload containing either class and, for an admitted file, retains the complete original byte image in source fidelity. Accepted sender-product and native-file-name strings become the corresponding source attributes.

## Directory Entry section

Each Directory Entry contains twenty fixed eight-byte fields across two cards. Blank numeric fields have their field-defined default. Nonblank numeric fields are right-aligned signed decimal integers.

The first card fields are entity type, Parameter Data start sequence, structure, line font pattern, level, view, transformation matrix, label-display associativity, and the eight-character status number. The second card fields are the repeated entity type, line weight, color, Parameter Data card count, form number, two reserved fields, entity label, and entity subscript. The repeated entity type must equal the first-card value. Reserved bytes are retained whether blank or nonblank.

The status number is exactly eight decimal digits interpreted as four two-digit fields: blank status, subordinate-entity switch, entity-use flag, and hierarchy. Spaces are not allowed in a nonblank status field. An entirely blank status field defaults all four fields to zero. This is the Status Number rule in [IGES 5.3 §2.2.4.4.9](https://paulbourke.net/dataformats/iges/IGES.pdf). A nonnegative Structure value is ignored. A negative Structure value is permitted only for Type 422 Forms 0 and 1, Type 402 Forms 5001 through 9999, and macro-instance types 600 through 699 or 10000 through 99999. Type 422 points to Type 322 Form 0. An implementor-defined Type 402 points to Type 302 with the same form number. A macro instance points to Type 306 or to a Type 416 external reference for a library definition. Other negative structure, line-font, level, view, transformation, label-display, or color values denote Directory Entry pointers where their fields permit an entity reference. Pointer parity and source-specific target type are validated after all entries are indexed.

Subordinate-entity switch `00` is independent, `01` is physically dependent, `02` is logically dependent, and `03` is both physically and logically dependent. A rule that requires physical dependence accepts `01` and `03`. A rule that requires logical dependence accepts `02` and `03`.

## Parameter Data section

Type 406 Forms 34 and 35 put `NP = 1 + 3*ND` at Parameter index 1 and `ND` at index 2 under [IGES 5.3 §§4.130–4.131](https://paulbourke.net/dataformats/iges/IGES.pdf). Each range stores the positive text-string index `T`, the positive first-character index `F`, and the positive last-character index `L` at indexes `3 + 3*i` through `5 + 3*i`, with `F <= L`; the last specified primary index is `2 + 3*ND`, so trailing pointer groups begin at token index `3 + 3*ND` after the entity type token. Form 34 has one General Note owner. Form 35 has one General Note or Text Display Template owner.

Type 128 Forms 0 through 9 put `K1`, `K2`, `M1`, and `M2` at Parameter indexes 1 through 4 under [IGES 5.3 §4.24](https://paulbourke.net/dataformats/iges/IGES.pdf). Let `A = 1 + K1 + M1`, `B = 1 + K2 + M2`, and `C = (K1 + 1) * (K2 + 1)`. The first and second knot sequences contain `A + 1` and `B + 1` values, the weight sequence contains `C` values, the control points contain `3*C` values, and the parameter range contains four values. The last specified primary index is `15 + A + B + 4*C`, so trailing pointer groups begin at token index `16 + A + B + 4*C` after the entity type token. A missing, negative, or degree-incompatible index, or an arithmetic overflow, has no usable entity-table boundary.

Type 144 Form 0 puts the support-surface pointer, outer-boundary flag, inner-boundary count `N2`, and outer-boundary pointer at Parameter indexes 1 through 4 under [IGES 5.3 §4.34](https://paulbourke.net/dataformats/iges/IGES.pdf). The `N2` inner-boundary pointers occupy indexes 5 through `4 + N2`; the last specified primary index is `4 + N2`, so trailing pointer groups begin at token index `5 + N2` after the entity type token. `N2 = 0` is valid; when the outer-boundary flag is zero, Parameter index 4 is the required zero/default field. A missing, negative, or overflowing `N2` has no usable entity-table boundary.

Type 143 Form 0 puts the boundary representation flag, support-surface pointer, and boundary count `N` at Parameter indexes 1 through 3 under [IGES 5.3 §4.33](https://paulbourke.net/dataformats/iges/IGES.pdf). The `N` Boundary Entity pointers occupy indexes 4 through `3 + N`; the last specified primary index is `3 + N`, so trailing pointer groups begin at token index `4 + N` after the entity type token. A nonnegative `N`, including zero, determines this table boundary. A missing, negative, or overflowing `N` has no usable entity-table boundary.

Type 114 Form 0 puts the u-segment count `M` and v-segment count `N` at Parameter indexes 3 and 4 under [IGES 5.3 §4.15](https://paulbourke.net/dataformats/iges/IGES.pdf). The primary layout has `M + 1` u breakpoints, `N + 1` v breakpoints, and 48 values for each block in the complete `(M + 1) * (N + 1)` patch-and-placeholder grid. The last row and column are placeholder values, but they remain in the Parameter Data list. The last specified primary index is `6 + M + N + 48*(M + 1)*(N + 1)`, so trailing pointer groups begin at token index `7 + M + N + 48*(M + 1)*(N + 1)` after the entity type token. A missing, nonpositive, or overflowing `M` or `N` has no usable entity-table boundary.

Type 110 Forms 0, 1, and 2 list six primary real values, `X1`, `Y1`, `Z1`, `X2`, `Y2`, and `Z2`, at indexes 1 through 6 under [IGES 5.3 §4.13](https://paulbourke.net/dataformats/iges/IGES.pdf), so their trailing pointer groups begin at token index 7 after the entity type token.

Type 116 Form 0 lists `X`, `Y`, and `Z` at indexes 1 through 3 and `PTR` at index 4 under [IGES 5.3 §4.16](https://paulbourke.net/dataformats/iges/IGES.pdf). `PTR` is the optional display-symbol pointer and may be zero. In free-formatted Parameter Data, a trailing field that functions as optional is represented as a required-default field under [§2.2.1](https://paulbourke.net/dataformats/iges/IGES.pdf): when the trailing pointer groups are present, index 4 is therefore either the supplied zero or an empty field, and the groups begin at token index 5. A record delimiter immediately after `Z` defaults the remaining fields, including both group counts, under [§2.2.3](https://paulbourke.net/dataformats/iges/IGES.pdf), so no trailing group is present.

Type 106 uses the form-required interpretation and tuple count to establish its boundary under [IGES 5.3 §§4.6–4.11](https://paulbourke.net/dataformats/iges/IGES.pdf): IP 1 has common Z at parameter index 3 and pairs through index `3 + 2*N`, so groups begin at token index `4 + 2*N`; IP 2 has triples through index `2 + 3*N`, so groups begin at token index `3 + 3*N`; IP 3 has sextuples through index `2 + 6*N`, so groups begin at token index `3 + 6*N`. Forms 1, 11, 20, 21, 31 through 38, 40, and 63 require IP 1; Forms 2 and 12 require IP 2; Forms 3 and 13 require IP 3. A missing, invalid, or form-disagreeing IP does not enable generic boundary recovery.

Form 63 requires IP 1 for its simple closed planar curve data. The NIST simple-closed-area application protocol makes this IP 1 requirement explicit under [IGES 5.0 application protocol guidance](https://www.govinfo.gov/content/pkg/GOVPUB-C13-361544732a3d339d5e4e866813938825/pdf/GOVPUB-C13-361544732a3d339d5e4e866813938825.pdf); the generic IP descriptions repeated in the Form 63 table do not change the form-specific planar layout.

Type 402 Forms 1, 7, 14, and 15 put `N` at Parameter index 1 and `N` member pointers at indexes 2 through `N + 1` under [IGES 5.3 §§4.81, 4.85, 4.89, and 4.90](https://paulbourke.net/dataformats/iges/IGES.pdf), so their trailing pointer groups begin at token index `N + 2`. Forms 1 and 14 require each member to carry a back pointer to the group. Forms 7 and 15 do not. The decoder applies this entity-specific boundary before generic recovery.

Type 402 Form 5 puts the positive label-placement count `N` at Parameter index 1 under [IGES 5.3 §4.84](https://paulbourke.net/dataformats/iges/IGES.pdf). Each placement has seven primary fields: `DEV(i)`, `XT(i)`, `YT(i)`, `ZT(i)`, `DEARRW(i)`, `LLN(i)`, and `DE(i)`, at indexes `2 + 7*(i - 1)` through `8 + 7*(i - 1)`. The last specified primary index is `1 + 7*N`, so trailing pointer groups begin at token index `2 + 7*N`. A missing, nonpositive, wrong-typed, overflowing, or list-truncated `N` has no usable entity-table boundary.

Type 402 Form 6 puts the fixed class-1 value `1` at Parameter index 1 and the nonnegative second-class count `N1` at index 2 under [IGES 5.3 Appendix F.5](https://paulbourke.net/dataformats/iges/IGES.pdf). The class-1 view pointer is at index 3; the class-2 visible-entity pointers occupy indexes 4 through `3 + N1`. The last specified primary index is `3 + N1`, so trailing pointer groups begin at token index `4 + N1`. `N1=0` is valid and produces an empty visible-entity list. The view and every visible entity require a trailing association back pointer to the Form 6 entity. A missing, non-integer, negative, overflowing, or list-truncated `N1`, or a class-1 value other than `1`, has no usable entity-table boundary.

Type 402 Form 12 puts the positive entry count `N` at Parameter index 1 under [IGES 5.3 §4.87](https://paulbourke.net/dataformats/iges/IGES.pdf). Each entry contains the External Reference Entity symbolic name at index `2 + 2*(i - 1)` and the internal Directory Entry pointer at index `3 + 2*(i - 1)`. The last specified primary index is `1 + 2*N`, so trailing pointer groups begin at token index `2 + 2*N`. A missing, nonpositive, wrong-typed, overflowing, or pair-truncated `N` has no usable entity-table boundary.

Type 402 Form 13 defines the legacy Dimensioned Geometry Associativity under [IGES 5.3 §4.88](https://paulbourke.net/dataformats/iges/IGES.pdf); Form 21 replaces it. Parameter index 1 is `ND` and must be `1`; index 2 is `NG`, the number of associated geometry entities; index 3 is `DIMPTR`, the dimension pointer; and indexes 4 through `3 + NG` are the geometry pointers. The last specified primary index is `3 + NG`, so trailing pointer groups begin at token index `4 + NG`. The dimension requires a trailing back pointer to the Form 13 entity; geometry entities do not require back pointers, and the association is unordered. The CADIR admission rule requires `NG>0` and a complete geometry list; a missing, nonpositive, wrong-typed, overflowing, or truncated `NG`, or an `ND` other than `1`, has no usable entity-table boundary.

Bytes 1 through 64 of Parameter Data cards form parameter fragments. Bytes 65 through 72 identify the owning odd Directory Entry sequence. Zero, an even sequence, and an absent Directory Entry sequence are invalid back-pointers. Fragments are grouped by that back-pointer and ordered by Parameter Data sequence. The Directory Entry Parameter Data start sequence and card count define the exact contiguous range. Every card in that range has the owning Directory Entry sequence, and no card outside the range has that owner. The count includes every owned card, including cards whose payload follows the record delimiter and contains comments. A disagreement is malformed input; the start pointer is the first Parameter Data sequence in [IGES 5.3 §2.2.4.4.2](https://paulbourke.net/dataformats/iges/IGES.pdf), the count is the number of lines in [§2.2.4.4.14](https://paulbourke.net/dataformats/iges/IGES.pdf), the card back-pointer is required by [§2.2.4.5.1](https://paulbourke.net/dataformats/iges/IGES.pdf), and comment lines remain in that count under [§2.2.4.5.3](https://paulbourke.net/dataformats/iges/IGES.pdf). A record delimiter terminates the entity's primary parameters. The primary parameters are followed, before that delimiter, by zero or one associativity pointer group and zero or one property pointer group. Each present group starts with its count and then that many Directory Entry pointers. Comments begin after the record delimiter and are not entity parameters. The entity table supplies `NV`, the last specified or defaulted primary parameter index, before the groups defined by [IGES 5.3 §2.2.4.5.2](https://paulbourke.net/dataformats/iges/IGES.pdf). Type 123 Form 0 has X, Y, and Z at indexes 1 through 3 under [§4.20](https://paulbourke.net/dataformats/iges/IGES.pdf), so its groups begin at token index 4 after the entity type token. The decoder uses a proven entity-table boundary before generic recovery. For an entity form without a usable registered primary layout, the CADIR recovery rule selects a suffix only when exactly one structurally closed candidate is fully target-valid. If no candidate or more than one candidate is target-valid, the decoder does not infer a boundary: it retains the complete token sequence as primary parameters and creates no association or property links. On a required back-pointer route, a structurally closed suffix whose pointers do not resolve remains visible as an invalid group; if no target-valid boundary exists and multiple structural candidates remain, the boundary is not guessed. A required back-pointer route with an ambiguous or invalid group emits a finding while retaining all raw tokens.

Tokens retain their exact source spans and lexical bytes. Token classes are integer, real, Hollerith string, Directory Entry pointer, omitted value, parameter delimiter, record delimiter, and retained uninterpreted value. An empty or blank-only Parameter Data field is an omitted value. A required-default integer or real field uses its defined explicit default or the data-type default zero. A logical field defaults to false. A string field defaults to the null string. A pointer field defaults to zero only when its entity field defines zero or default semantics. Count fields and non-null constituent pointers are required-no-default fields. A supplied token must have the field's lexical type; a wrong-typed token does not select a default. A record delimiter supplies every remaining trailing required-default field. Entity accessors impose field-specific token types and arity. Pointer interpretation is field-specific; a numeric token is not globally coerced to a pointer. These are the field-category and free-format rules in [IGES 5.3 §§2.2.1–2.2.3](https://paulbourke.net/dataformats/iges/IGES.pdf).

Semantic output writes every finite nonzero real directly with 17 significant decimal digits and a `D` exponent, declares 17 double-precision significant digits in Global field 11, and writes either sign of zero as `0`. It does not apply a comparison tolerance or lower-precision pre-rounding during serialization. This CADIR writer profile round-trips every finite binary64 value without flushing small nonzero values to zero. Generated Parameter Data cards end immediately after a parameter or record delimiter. A generated token longer than the 64-byte Parameter Data area is refused. Card boundaries have no token semantics on input; delimiter-aligned output is an interoperability convention.

A semantic edge parameter range has a finite start strictly less than its end. A zero-length range is a degenerate edge and is refused; it is never promoted to a revolution. An unreferenced circle or ellipse uses one complete revolution. A referenced circular or elliptical edge whose model-space start and end points are identical is also complete. Generated complete Type 100 and Type 104 arcs copy the two start-coordinate tokens to the terminate coordinates byte for byte.

A declared count applies only when the complete counted sequence fits before the end of the entity-specific parameters. The entity layouts that establish these widths are defined by [IGES 5.3 §§4.6–4.7, 4.14–4.16, 4.46, 4.58–4.62, 4.67–4.70, 4.73, 4.77–4.79, 4.80–4.96, 4.97–4.107, 4.123, 4.126, 4.136–4.137, and 4.141](https://paulbourke.net/dataformats/iges/IGES.pdf); the entity-specific boundary precedes the trailing pointer groups defined by [§2.2.4.5.2](https://paulbourke.net/dataformats/iges/IGES.pdf). Fixed-width items require `count * width` tokens. Under [§2.2.3](https://paulbourke.net/dataformats/iges/IGES.pdf), a record delimiter may supply trailing default fields for the final item; those omitted source tokens do not cross the entity-specific boundary, and the final item start must still fit before it. If a nested counted sequence is incomplete, its declared count remains present, its typed item list is empty, and no later token is reinterpreted as the start of a sibling item. Every counted native record retains its declared count separately from its typed items. Type 402 Forms 9, 13, 16, 18, 20, and 21 retain their child, geometry, entity, flow, connection, join, name, name-display, and continuation counts as applicable. The decoder applies this rule at the selected entity-specific boundary. Every semantic projector uses that same boundary for fixed fields and counted lists; trailing pointer groups remain relationship data and are not entity fields. This is a CADIR recovery decision: if an item in a native outer list or a nested counted sequence is incomplete, that projected list is empty; raw Parameter Data tokens remain in the native entity record, and later sibling fields are read only after preceding variable-width lists are complete.

Type 406 Form 11 puts `NP`, `PTYPE`, `ND`, and `NI` at Parameter Data indexes 1 through 4 under [IGES 5.3 §4.107](https://paulbourke.net/dataformats/iges/IGES.pdf). `TYPI(1..NI)` occupies indexes `5..4+NI`; `NVALI(1..NI)` occupies indexes `5+NI..4+2*NI`; the `VALI` lists follow in independent-variable order; and the `VALD` list follows the complete `VALI` span. ## Entity graph

The entity identity is its odd Directory Entry sequence. Graph construction indexes all identities before resolving references. Each pointer evaluation has resolved, null, dangling, out-of-range, even-sequence, wrong-type, or cyclic resolution. A zero pointer has null resolution and creates no edge because it specifies no relationship; the raw zero remains in the native Directory Entry record. Each edge records the source entity, source field or parameter index, raw pointer, expected target class, and non-null resolution state. A value that cannot identify a Directory Entry because its sign or magnitude is invalid has out-of-range resolution. Each unresolved edge is a `reference_graph_not_closed` loss with the source Directory Entry identity and byte offset. Transformation links compose recursively and a transformation cycle has cyclic resolution. The other Directory Entry links select definitions or display entities and do not compose into same-kind reference chains.

Parameter Data pointer sign interpretation is field-specific. A positive pointer uses its value as the Directory Entry sequence. A field that defines a negative pointer encoding uses the negated magnitude and retains the signed raw value. A nonzero candidate resolves only if its sequence fits `u32`, is odd, identifies an existing Directory Entry, and satisfies the field's entity-type, form, and Directory-status target class. Only a resolved parameter pointer creates a typed arena identity. An unresolved parameter pointer leaves the typed arena field null and remains a reference edge. Its loss offset identifies the first byte of the source parameter token.

An entity retains its type, form, Directory Entry fields, status fields, ordered parameter tokens, trailing association and property groups, source spans, and reference edges. Unsupported type/form pairs remain named native records and prevent any support claim whose closed envelope admits the pair.

## Units and transformations

Model-space lengths equal native values divided by the Global model-space scale and converted from the declared unit to millimetres. Dimensionless values, parameter coordinates, weights, and unit direction vectors are not length-scaled. Angles convert to radians when projected to neutral IR. A transformation matrix is a 3-by-3 linear part plus translation. Translation is length-valued. Entity transforms compose from the entity definition toward model space exactly once. Definition, subfigure-instance, and occurrence transforms remain separate native relationships.

## Geometry

Type 116 Form 0 stores one finite model-space point. Type 123 Form 0 stores three finite dimensionless direction components and is physically dependent. Type 108 Form 0 stores a plane through the origin of its Directory transformation with local X and Y axes from that transformation; its local Z axis is the plane normal.

Type 124 Forms 0 and 1 define right-handed and left-handed affine transformations under [IGES 5.3 §4.21](https://paulbourke.net/dataformats/iges/IGES.pdf). The 3-by-3 linear part is orthonormal. Form 0 requires determinant `+1` and Form 1 requires determinant `-1`; the translation vector is arbitrary. IGES defines real fields as system-dependent approximations bounded by the declared Global precision, but does not prescribe a receiver tolerance or comparison algorithm for these matrix invariants. CADIR therefore admits a tokenized linear part when outward intervals derived from each real token's declared representation uncertainty contain `1` for every column norm, `0` for every distinct-column dot product, and the form's required determinant in the determinant interval. This is a CADIR admission policy, not an IGES tolerance, and it does not use a separate fixed epsilon. Arithmetic interval bounds are rounded outwards. After these invariants hold, the decoder canonicalizes the rounded linear coefficients to an orthonormal frame and preserves the three translation coefficients. Nested transformations compose those canonical frames.

IGES requires unit vectors for the planar Type 126 normal, the Type 130 offset-curve plane normal, the Type 140 offset indicator's surface normal, and the axes and sweep directions in Types 150 through 168 under [IGES 5.3 §§4.23, 4.25, 4.30, and 4.37–4.45](https://paulbourke.net/dataformats/iges/IGES.pdf). Types 150, 152, and 168 additionally require their local X and Z vectors to define an orthogonal frame; the local Y vector is their Z-into-X cross product and the X vector has accuracy precedence. IGES defines these geometric conditions but no receiver tolerance or comparison algorithm for approximate real tokens. CADIR admits a declared unit vector when outward component-uncertainty intervals produce a squared-norm interval containing `1`, and admits an orthogonal pair when the interval of their dot product contains `0`. This is a CADIR admission policy, not an IGES tolerance, and it uses no fixed epsilon. A failed check retains the native entity and suppresses its neutral projection. A geometric vector that passes admission is normalized before it defines a neutral direction. Type 123 is different: its source invariant is finite, nonzero components, not unit length.

Pointer-defined analytic surfaces use odd Directory pointers to Type 116 location points and physically dependent Type 123 direction entities. A referenced Type 123 entity has Form 0, has no transformation matrix, has three numeric finite components, and defines a nonzero vector. Type 190 Forms 0 and 1 define a plane from a location and normal, with Form 1 adding a reference direction. Type 192 Forms 0 and 1 define a circular cylinder from a location, axis, positive radius, and a Form 1 reference direction. Type 194 Forms 0 and 1 define a circular cone from a location, axis, nonnegative radius, semi-angle in degrees in `(0, 90)`, and a Form 1 reference direction. Type 196 Forms 0 and 1 define a sphere from a center and positive radius, with Form 1 adding its polar axis and reference direction. Type 198 Forms 0 and 1 define a torus from a center, axis, positive major and minor radii satisfying `minor < major`, and a Form 1 reference direction. Form 0 derives a stable perpendicular frame from the axis. Each Form 1 reference direction must resolve. It is projected into the plane normal to the axis and must remain nonzero.

Type 130 Form 0 defines a planar offset of a base curve. FLAG `1` uses one uniform distance, `2` interpolates two distances as a function of arc length or native parameter, and `3` takes one coordinate of another curve as the distance function. A real or integer parameter that is unused for the selected FLAG is zero or omitted; omission selects that data type's implicit zero. The unused DE2 pointer is an explicit integer zero because pointer fields have no implicit default unless their field definition declares one.

Type 106 interpretation flag IP and Directory form are redundant required constraints under [IGES 5.3 §§4.6–4.11](https://paulbourke.net/dataformats/iges/IGES.pdf). Forms 1, 11, 20, 21, 31 through 38, 40, and 63 require IP `1` for planar coordinate pairs with one common Z value. Forms 2 and 12 require IP `2` for coordinate triples. For an absent, out-of-range, or form-disagreeing IP, the CADIR native entity retains the raw Parameter Data; its typed `copious_data` record retains the parsed IP when present and the declared tuple count but exposes no typed tuples or `common_z`, and semantic projection records the source-attributed `iges/entity.not-projected` loss.

Type 106 Forms 11 through 13 define linear paths parameterized from zero through `N - 1`, with one unit parameter interval per consecutive point pair. Segments may cross or coincide, so consecutive duplicate points remain zero-length segments in the ordered path. The source point order is the curve order and is retained. Form 63 defines a simple closed planar path under [IGES 5.3 §§4.6–4.7, 4.11, 4.68, and Appendix K](https://paulbourke.net/dataformats/iges/IGES.pdf). Its first and last points are coincident under the Global minimum resolution rule: distance zero or distance strictly less than that resolution. No other pair of points may be coincident under that rule, and a two-point zero-length path is invalid. The simple-closed condition also prohibits crossing, touching, or overlapping away from the shared endpoint of adjacent segments and the one closure endpoint shared by the first and last segments. The projected Form 63 edge uses one shared endpoint vertex. The edge and vertex carry the positive Global minimum resolution as their topology tolerance.

Type 102 Form 0 defines one directed composite curve under [IGES 5.3 §4.4](https://paulbourke.net/dataformats/iges/IGES.pdf). Its defining list is ordered and may contain Point, Connect Point, and parameterized curve entities, excluding another Composite Curve; each constituent entity is physically dependent. Parameter index 1 is `N`, the number of constituent entities, and indexes 2 through `N + 1` are the ordered constituent pointers, so its trailing pointer groups begin at token index `N + 2` after the entity type token. The terminate point of each constituent curve must have the same coordinates as the start point of the succeeding curve. Point and Connect Point entities attach properties or logical connections and do not contribute to the composite parameterization. The Global minimum-resolution field defines the receiver rule that coordinate locations less than that value apart are coincident under [§2.2.4.3.19](https://paulbourke.net/dataformats/iges/IGES.pdf), and NIST IR 4600 RP 253 identifies a valid piecewise-continuous composite curve as a use of coincident-point testing while permitting either a box or Euclidean metric. CADIR uses Euclidean distance strictly less than the Global minimum resolution for curve-join and curve-endpoint admission; a zero resolution requires exact equality. The neutral carrier concatenates bounded curve constituents in source order. CADIR decision: a Point or Connect Point member does not add a neutral segment or parameter span, and a list with a non-curve member, no supported bounded curve carrier, an inadmissible join, or an empty or unevaluable concatenation remains in the native ordered Type 102 record and records a geometry loss; no bridge geometry is synthesized.

Curve parameters use the entity-defined native domains under [IGES 5.3 §§4.3–4.7, 4.11, 4.13–4.14, 4.23, and 4.25](https://paulbourke.net/dataformats/iges/IGES.pdf). A Type 100 circular arc uses its absolute definition-space angle from the positive X axis, with the terminate angle increased by one turn when required by counterclockwise order. A coincident start and terminate point denotes one complete turn. A Type 104 conic arc uses the family parameter defined by its standard-position conic: angle for an ellipse, signed axial coordinate for a parabola, or the bounded branch parameter for a hyperbola. A Type 110 Form 0 line uses `[0, 1]`; Forms 1 and 2 use `[0, +∞)` and `(-∞, +∞)` and have no bounded edge domain. A Type 106 linear path uses `[0, N - 1]`; point and presentation forms do not define curve domains. Form 63 uses the same domain as Form 11. A Type 112 spline uses `[T(1), T(N+1)]`. A Type 126 curve uses `[V(0), V(1)]`. A Type 102 composite starts at zero and gives each child a span equal to its native terminate parameter minus its native start parameter; a composite made only of point or connect-point entities has no parameterization. Neutral line geometry uses distance along its unit direction, and neutral Type 100 circle geometry uses angle from the arc start direction. The neutral Type 104 hyperbola carrier uses an equivalent `sinh`/`cosh` parameter, so its native secant/tangent parameter is not treated as an affine neutral interval. Type 130 requires `TT1` and `TT2` to lie in the base curve's native domain; `PTYPE = 1` measures the offset law by arc length from `r(TT1)`, and `PTYPE = 2` uses the base parameter. The decoder maps `TT1`, `TT2`, and parameter-basis distance controls from the source native domain to the neutral evaluation domain. Its affine native-to-neutral domain map covers bounded Types 100, 102, linear-path 106, 110 Form 0, 112, 126, and nested 130 sources; the source must still have an exact supported offset carrier. Other source parameterizations remain native and produce a named loss when no exact offset mapping and carrier are available.

Type 104 defines a nondegenerate ellipse, hyperbola, or parabola in an XY-parallel plane under [IGES 5.3 §4.5](https://paulbourke.net/dataformats/iges/IGES.pdf). Standard position requires each conic axis to be parallel to X or Y and centers the conic on the Z axis; a parabola has its vertex on that axis. An axis-aligned parabola may open along X or Y. A Directory Type 124 transformation moves the standard-position conic into model space. Forms 1, 2, and 3 identify ellipse, hyperbola, and parabola, but the form is informational; the coefficients determine the conic family. Form 0 is the deprecated unspecified form. The six coefficients define the parent conic and the ordered start and terminate coordinates define its bounded portion. Both fields are part of the format meaning: the coefficient-defined carrier supplies the conic and the endpoint fields supply its ordered bounds; neither field overrides the other. IGES defines no numeric endpoint-on-carrier consistency test or required receiver disposition for a disagreement. The CADIR decoder evaluates each endpoint on the coefficient-defined carrier, retains the declared endpoint coordinate as the edge vertex, and admits the entity only when the distance is zero or strictly less than the Global minimum resolution under [IGES 5.3 §2.2.4.3.19](https://paulbourke.net/dataformats/iges/IGES.pdf). That resolution is the tolerance of the projected edge and endpoint vertices when it is positive. Standard-position coefficient admission uses `S = max(1, |A|, |B|, |C|, |D|, |E|, |F|)` and `ε = S × 10^-12`; `B` is zero within `ε`, and at least one of `D` and `E` is zero within `ε`. A value outside this project gate retains the native entity and emits the source-attributed `entity.not-projected` loss; it produces no neutral conic.

Type 126 has positive weights and a nondecreasing knot vector under [IGES 5.3 §§2.2.4.3.9–2.2.4.3.11, 2.2.4.3.19, 4.23, and Appendix B §B.4](https://paulbourke.net/dataformats/iges/IGES.pdf). Directory Form Number 0–5 records a preferred analytic type; it does not change the Type 126 parameter interpretation or carrier. The four property flags are consistency claims about the values, not alternate geometry definitions. `PROP1 = 1` requires the control-point curve to lie in the declared plane and the final normal fields to contain a declared unit normal; the normal fields shall exist but are ignored when the curve is nonplanar. `PROP1 = 0` is required for a curve without a unique plane. `PROP2` is `1` exactly when the evaluated active-range endpoints at `V(0)` and `V(1)` coincide: their distance is zero or strictly less than the Global minimum resolution. `PROP3 = 1` is required when all positive weights agree within their declared real representation uncertainty; the projected polynomial omits weights because their common factor cancels. `PROP3 = 0` requires unequal positive weights and preserves them. `PROP4` records periodicity but is informational and does not replace the coefficient-defined carrier or alter its evaluation. A contradictory `PROP1`, `PROP2`, or `PROP3` is invalid. The active parameter range satisfies `T(0) <= V(0) < V(1) <= T(N)`. A declared range endpoint outside its active knot bound by no more than the combined representation uncertainty is clamped to that bound. A larger disagreement is invalid.

Type 112 defines each segment coordinate as `a + b*w + c*w^2 + d*w^3`, where `w = u - T(i)`, under [IGES 5.3 §4.14](https://paulbourke.net/dataformats/iges/IGES.pdf). The uncertainty interval for `w` is the interval of `T(i+1) - T(i)`. Interval arithmetic propagates the breakpoint and coefficient uncertainties through `w`, `w^2`, and `w^3`. Every segment has at least one nonzero coefficient among its nine `B`, `C`, and `D` values. At every interior breakpoint, the terminal point and the next segment's start point must be separated by a distance strictly less than the Global minimum resolution; when that resolution is zero, the points must coincide exactly. `H = 0` requires this positional continuity. `H = 1` also requires slope continuity with respect to arc length. `H = 2` also requires curvature continuity with respect to arc length. The Global minimum-resolution comparison applies to positional continuity only; [NIST IR 4600 RP 253](https://nvlpubs.nist.gov/nistpubs/Legacy/IR/nistir4600.pdf) explicitly excludes it from slope and curvature checks. For CADIR admission, the unit tangent is `r'(u) / |r'(u)|`, curvature is the derivative of that unit tangent with respect to arc length, and the corresponding real-token uncertainty intervals are required to overlap in every component at each applicable join. IGES defines no numeric receiver tolerance or comparison algorithm for these derivative conditions, so this interval-overlap test is a CADIR decision, not an IGES tolerance. CADIR decision: a Type 112 entity that fails a required continuity, planarity, or nondegeneracy condition remains native and does not produce a neutral carrier. For `NDIM = 2`, each `BZ`, `CZ`, and `DZ` interval must contain zero. The final twelve values are redundant evaluations of the last polynomial and its first three factorial-scaled derivatives. CADIR decision: a missing or nonfinite terminal block prevents projection. If a present terminal block disagrees with the coefficient-defined values, CADIR records a source-attributed loss, retains the coefficient-defined carrier, and does not replace or discard it because the block is redundant.

Type 112 curve type, continuity class, and dimensionality are retained in the native entity's ordered parameter tokens. The neutral spline carrier uses the validated coefficient geometry and does not encode the curve type, continuity class, or dimensionality; a successful Type 112 projection emits `geometry.spline-header-not-transferred` with source provenance. Type 114 curve type and patch type follow the same rule: the native entity retains both header fields, the neutral NURBS carrier retains the validated patch geometry, and a successful projection emits the same loss code.

Curve and surface projection and semantic conic writing use one absolute angular tolerance of `2π × 10^-12` radians. This is a codec representation policy, not a tolerance encoded by an IGES entity. An arc whose endpoint directions differ by no more than this tolerance is a complete turn. A revolution whose sweep differs from `2π` by no more than this tolerance is periodic. A sweep may exceed `2π` by this tolerance and is then clamped to `2π` before exact carrier construction.

## Primitive solids

Primitive solid entities use Form 0. Their native dimensional values remain in declared model units, their origin defaults to `(0,0,0)`, and their axis vectors are dimensionless. An omitted X axis defaults to `(1,0,0)` and an omitted Z or revolution axis defaults to `(0,0,1)`. Every supplied or defaulted axis is unit length. Entities carrying both X and Z axes require them to be orthogonal; local Y is `Z × X`. The Directory transformation remains a separate placement link.

Type 150 stores three positive block lengths, origin, X axis, and Z axis. Type 152 adds a nonnegative top X length strictly smaller than its positive base X length; its Y and Z lengths are positive. Type 154 stores positive cylinder height and radius, its first-face center, and axis. Type 156 stores positive frustum height, a positive large radius, and a smaller radius in `[0, large_radius)`; the small radius defaults to zero. Type 158 stores a positive sphere radius and center. Type 160 stores torus major and minor radii with `major > minor > 0`, center, and axis. Type 168 stores ellipsoid radii with `X ≥ Y ≥ Z > 0`, center, X axis, and Z axis.

The `native.iges` `primitive_solids` arena retains the typed primitive kind, named native dimensions, omitted-versus-present origin and axis components, source entity, and transformation link. Invalid dimensions, axes, units, or transformation chains prevent semantic decoding while the generic native entity remains intact.

Type 162 defines a solid of revolution from a profile-curve pointer, a revolution fraction in `(0,1]` defaulting to `1`, an axis origin defaulting to `(0,0,0)`, and a unit axis defaulting to `(0,0,1)`. Form 0 requires an open profile whose endpoints close to the axis by projection. Form 1 carries a profile whose area is closed by the profile itself or by joining its endpoints. Type 164 defines a linear extrusion from a closed profile, a positive length, and a unit direction defaulting to `(0,0,1)`. Both retain their Directory transformation as the resulting solid's placement.

Type 180 Forms 0 and 1 store a postorder regularized Boolean expression under [IGES 5.3 §4.46](https://paulbourke.net/dataformats/iges/IGES.pdf). The declared term count is greater than two. Negative terms are negated odd Directory pointers to solid operands; positive terms `1`, `2`, and `3` mean union, intersection, and difference. Each operation consumes two stack values and produces one. The stack never underflows and contains exactly one value after the final term. Operand links are acyclic. Form 0 admits primitive, solid-instance, and other Boolean-tree operands and excludes a direct Manifold Solid B-rep Object operand. Form 1 admits the same operand classes and requires at least one immediate operand whose Directory entity is a Manifold Solid B-rep Object (Type 186). A nested Type 180 is an operand of the outer tree, not a Type 186 operand, so a Type 186 descendant does not satisfy the outer Form 1 requirement. A Type 430 Form 1 solid instance remains a solid-instance operand and does not satisfy the direct Type 186 requirement. A nested Boolean-tree operand must itself be a valid Boolean tree with its declared form. The typed `boolean_trees` arena retains ordered operands and operations without converting the expression to an unordered relationship graph.
Type 180 puts `N` at Parameter index 1 and stores the `N` postorder operation-or-operand terms at indexes 2 through `N + 1`, so the first trailing pointer-group count is token index `N + 2`. `N` is a usable table boundary only when it is an integer greater than two and all `N` terms fit before the record delimiter. A complete counted span keeps this boundary even when an individual term has the wrong lexical value or an invalid operation or operand; semantic Boolean projection retains the native terms and reports the Boolean loss. A missing, nonpositive, `N <= 2`, overflowing, or truncated length or term span has no usable Type 180 boundary. The CADIR decision for that malformed known layout is to retain all raw Parameter Data tokens and suppress generic trailing-pointer recovery.

Type 182 Form 0 selects one connected component of a disjoint Boolean result. It has entity-use flag `03`, a pointer to a semantically decoded Type 180 tree, and a finite model-space point in or on the selected component. The `selected_components` arena retains the tree identity, native selection coordinates, source identity, and optional Directory transformation.

The `native.iges` `procedural_solids` arena retains sweep kind, form, profile identity, native sweep amount, omitted-versus-present axis fields, and transformation link. Semantic decoding requires a decoded profile carrier and closure consistent with the owning form.

The `product_occurrences` arena expands every top-level Type 408 and Type 420 instance through nested Type 308 and Type 320 members. Occurrence identity is the complete ordered instance path, so repeated uses of one source instance remain distinct. Each occurrence stores its source instance, referenced definition, optional leaf member, neutral body, point, curve, or surface identities emitted from that leaf, local affine transform, and composed world affine transform in millimetres. Local placement applies definition-space scale, then instance translation, then the instance Directory transformation. A leaf member's Directory transformation is applied after its containing occurrence transform. Expansion is bounded to 64 nested instances, terminates on repeated source instances, and emits at most 100,000 occurrence records. IGES defines subfigure nesting and placement in [IGES 5.3 §3.6.2](https://paulbourke.net/dataformats/iges/IGES.pdf), but does not define a top-level occurrence root or malformed-list recovery. CADIR identifies roots as Type 408 or Type 420 instances that are not members of a valid Type 308 or Type 320 definition. During semantic decode, only Type 308 and Type 320 definitions and Type 408 and Type 420 instances admitted by the structure projection participate in occurrence expansion; an invalid definition or instance remains in its native arena with its structure loss and produces no occurrence. During container-only decode, semantic structure admission is not requested, so the native arenas expand every parseable Type 308 or Type 320 definition and Type 408 or Type 420 instance using the same raw member-list, root, and placement rules. This is a CADIR decision. Root inference is all-or-nothing: every Type 308 and Type 320 member list must have a nonnegative declared count and an odd, in-file Directory pointer for every declared member. If any member list is malformed, the decoder suppresses root inference for the document because the unresolved member can be any instance. It retains the typed definition and instance records; each invalid member slot in a traversable declared list is null, and it emits one source-attributed `occurrence.root-inference-blocked` warning for each malformed definition. An omitted placement field uses its entity default. A supplied placement field with the wrong lexical type, a nonfinite value, a nonpositive scale, or an unresolved transformation is malformed. CADIR retains the raw and typed source records, emits a source-attributed `occurrence.placement-malformed` warning, and emits no occurrence for the affected instance or leaf member, including when semantic structure admission excludes that instance. Typed placement projections use the same admission rule. The `product_occurrence_expansion` arena records both limits, the emitted count, the combined truncation state, and an ordered issue list containing `output_limit`, `depth_limit`, `malformed_definition`, or `malformed_placement`. Each issue produces a decode loss.

Every entity may append two counted pointer groups after its entity-specific parameters. The first contains Type 402 associativity, Type 212 general-note, or Type 312 text-display-template pointers. The second contains Type 316 units data, Type 406 property, Type 322 attribute-table definition, or Type 422 attribute-table instance pointers. Under [IGES 5.3 §2.2.4.5.2](https://paulbourke.net/dataformats/iges/IGES.pdf), the groups follow all other specified or defaulted parameters and precede the record delimiter. A candidate suffix is structurally closed when its nonnegative counts consume the complete remaining token sequence and at least one pointer is present. A candidate is target-valid when every association pointer is odd and names Type 402, Type 212, or Type 312, and every property pointer is odd and names Type 316, Type 322, Type 406, or Type 422. When the entity table supplies `NV`, the suffix at `NV + 1` is the only boundary considered. Otherwise, the typed suffix is the unique target-valid candidate under the CADIR generic recovery rule. Its start is the primary-parameter end, its pointers are parameter-reference graph edges, and the native entity's `association_links` and `property_links` preserve resolved group membership and pointer order independently from Directory references. If no candidate is target-valid, or if more than one generic candidate is target-valid, the decoder does not infer a boundary: it retains the complete token sequence as primary parameters and creates no association or property links. In the multiple-valid case it emits one `parameter.boundary-ambiguous` loss with the owning Directory provenance before native projection.

Type 402 Forms 1 and 14 provide independent evidence that each listed member has a trailing associativity group. For a listed member, more than one structural candidate with no target-valid candidate also emits `parameter.boundary-ambiguous`; a single structurally closed target-invalid candidate remains untyped for pointer diagnostics. Each candidate pointer is classified in the reference graph. An unresolved candidate produces `reference_graph_not_closed` at its exact parameter-token offset. Candidate pointers do not create `association_links` or `property_links`. Arithmetic closure without this reverse relationship does not establish a malformed suffix because ordinary entity parameters can have the same counted shape. The complete original token sequence remains in `parameters`.

## Topology

Manifold solid B-rep entities preserve source vertex, edge, loop, face, shell, and solid identity. Edge uses reference shared edge identity; loop orientation and face same-sense fields determine coedge and face orientation. A solid region's ordered shell list is the neutral role contract: the decoder stores the Type 186 `SHELL` pointer first and the void-shell pointers afterward in source order, and the writer emits that order. Type 186 writes the first shell as `SHELL` and the remaining shells as its ordered void list. The writer does not infer or replace these roles from geometric containment.

Every use of one Edge List item in a shell belongs to one cyclic radial ring. A closed Form 1 shell requires exactly two opposite-sense uses per edge. An open Form 2 shell preserves one, two, or more uses without imposing the closed-manifold cardinality rule; rings with more than two uses represent explicit non-manifold sharing.

A Form 1 Edge List Entity (Type 504) stores a positive ordered list of model-space curve pointers and one-based start and end indices into Form 1 Vertex List entities. Evaluating the curve at its stored parameter interval endpoints must agree with the referenced vertex points within the Global minimum resolution. An inconsistent edge prevents attachment of every topology candidate that consumes it. The edge-list order is not an ownership signal.

A Form 1 Loop Entity (Type 508) stores a positive ordered use count. Each use selects an Edge List or Vertex List item, stores an orientation logical, and stores an arbitrary ordered sequence of `(ISOP, CURV)` parameter-curve pairs. Each `ISOP` field is a required logical: true declares that its parameter-space curve is isoparametric on the face surface, and false declares that it is not. These meanings and the field layout are defined by [IGES 5.3 §4.145](https://paulbourke.net/dataformats/iges/IGES.pdf). Edge uses become coedges. Vertex uses become pole uses positioned after the preceding edge use in cyclic loop order, or the sole unanchored use of a vertex-only loop. Every parameter curve remains ordered and retains its isoparametric logical. The parameter-curve collection forms one connected parameter-space image. Composing its first endpoint, adjacent joins, and final endpoint with the face surface must agree with the oriented edge vertices within the Global minimum resolution. A pole-use collection has the same endpoint contract with the pole vertex. Disagreement prevents attachment of the containing topology candidate.

For CADIR B-rep projection, a Type 508 edge use may obtain its neutral source Edge range only from exactly one source occurrence whose curve identity matches the Type 504 carrier and whose retained parameter-interval endpoints agree with the Type 504 start and terminate vertices within the Global minimum resolution. Zero matches or multiple matches refuse the topology candidate. The decoder does not select a source occurrence by Edge List order. The Type 504 carrier and the Type 508 use semantics are defined by [IGES 5.3 §§4.144–4.145](https://paulbourke.net/dataformats/iges/IGES.pdf).

A Form 0 Bounded Surface Entity (Type 143) has one `TYPE` representation value for all of its Boundary Entities. `TYPE=0` requires every Boundary Entity to contain model-space curves only; `TYPE=1` requires every Boundary Entity to contain model-space curves and associated parameter-space curve collections. These requirements are defined by [IGES 5.3 §§4.31 and 4.33](https://paulbourke.net/dataformats/iges/IGES.pdf). Semantic output rejects an unclassified face whose boundary loops do not all have the same parameter-curve presence; it does not select the value from loop order or alter a loop's representation.

A Form 1 Face Entity (Type 510) stores a support-surface pointer, a positive loop count, an outer-loop logical, and the ordered loop pointers. When the logical is true, the first loop is the sender-selected outer loop and the remaining loops are the other bounds. When it is false, no outer loop is identified. The semantic writer emits the logical only from an explicit `outer` role, refuses a mixture of classified and unclassified B-rep loops, and emits false for an entirely unclassified face. The decoder maps a false logical to `Unspecified`; it does not invent an inner role. A cylindrical face boundary loop that repeats one seam edge without an axial boundary does not delimit a finite region and is refused by the semantic writer.

Boundary and curve-on-surface entities are valid independent entities and do not require a bounded-surface or trimmed-surface owner. When a bounded-surface or trimmed-surface entity consumes them, they carry face-local boundaries and produce sheet regions whose loops, coedges, edges, and vertices are owned by the source face. No cross-face edge sharing is inferred without a shared source topology entity. A topology candidate is attached only after the complete neutral ownership and reference graph validates. A failed topology candidate records a loss only on its owning bounded-surface or trimmed-surface entity.

Face-local carrier agreement uses the Global minimum resolution in model units. Boundary-ring closure uses a topology sewing tolerance equal to the larger of the Global minimum resolution and one coordinate quantum at the largest absolute endpoint coordinate, where the quantum follows the Global single-precision significant-digit count. Boundary endpoints use the transitive closure of that tolerance relation. A connected component whose diameter exceeds the tolerance is non-transitive and invalid; it does not select a representative by source order. A valid component uses its lexicographically smallest endpoint as its representative. Local vertex identities follow first endpoint order and are names only; they do not select the topology cluster. The resulting vertices, edges, and face store that sewing tolerance. Exact conversion of a source parameter curve to neutral NURBS geometry has no fit tolerance; the Global resolution is not recorded as an approximation bound.

Declared surface parameter domains remain attached to the exact procedural surface construction. Type 118 retains the active first-rail interval and the interpolation interval `[0, 1]`. Its direction flag reverses the second rail without changing the surface parameter domain. Its developability flag is retained in the native entity's ordered parameter tokens but is not represented by the neutral ruled-surface carrier; a successful Type 118 projection emits `geometry.ruled-developability-not-transferred` with source provenance. Type 120 retains the generatrix interval and `[SA, TA]`. Type 122 retains the directrix interval and `[0, 1]`. Type 128 retains its increasing `[U(0), U(1)]` and `[V(0), V(1)]` subranges both as ordered exact-surface parameters and as record bounds. A Type 128 bound outside its active knot domain by no more than its declared real representation uncertainty is clamped to the domain endpoint. A larger disagreement, an empty interval, or a permutation of the four range fields is invalid. A periodic parameter may use one unwrapped period at a seam; the equivalent interval remains within the declared periodic domain.

Type 140 evaluates the oriented unit normal of its support at `(Um, Vm)` under [IGES 5.3 §4.30](https://paulbourke.net/dataformats/iges/IGES.pdf). A bounded support uses `Um = (U0 + U1) / 2` and `Vm = (V0 + V1) / 2`; an unbounded support uses `(0, 0)`. The declared offset indicator must agree, within its real representation uncertainty, with that normal or its negation. Agreement selects positive support-normal distance; negation selects negative support-normal distance. An arbitrary unit vector is not an offset indicator. The indicator selects the sign only and does not replace the varying normal field used to evaluate the offset.

A Form 0 Boundary Entity (Type 141) stores `TYPE`, `PREF`, the support-surface pointer, and a positive model-curve count. Each ordered model-curve item stores its curve pointer, sense (`1` forward or `2` reversed), pcurve count, and that many parameter-curve pointers. `TYPE=0` requires every pcurve count to be zero. `TYPE=1` requires every pcurve count to be positive. The parameter curves of one item remain ordered and together form that coedge's parameter-space image. These `TYPE` meanings are defined by [IGES 5.3 §4.31](https://paulbourke.net/dataformats/iges/IGES.pdf).

For Type 141, item `i` starts at Parameter index `5 + 3*(i - 1) + K(1) + ... + K(i - 1)`. Its three fields are `CRVPT(i)`, `SENSE(i)`, and `K(i)`, followed by `K(i)` `PSCPT(i,j)` pointers. The last specified primary index is `4 + 3*N + K(1) + ... + K(N)`, so trailing pointer groups begin at token index `5 + 3*N + K(1) + ... + K(N)` after the entity type token. `N` is positive; every `K(i)` is nonnegative, and `TYPE=0` requires `K(i)=0` for every item. A missing, nonpositive, negative, or overflowing count has no usable entity-table boundary.

Type 141 `PREF=1` selects the model-space trimming curves for neutral topology. Values `0`, `2`, and `3` select the parameter-space collections when present and require their composed endpoints to agree with the model-space curves. The four Type 141 preference meanings are defined by [IGES 5.3 §4.31](https://paulbourke.net/dataformats/iges/IGES.pdf). The associated parameter-space curves must remain inside each finite declared support bound over their active ranges. An out-of-domain alternate is omitted when the model-space curve is preferred and invalidates the topology candidate when parameter curves are authoritative. Type 142 reverses the numeric preference roles: `PREF=1` selects the composed parameter-space curve, `PREF=2` selects the model-space curve, and values `0` and `3` use both equally. These preference meanings are defined by [IGES 5.3 §4.32](https://paulbourke.net/dataformats/iges/IGES.pdf). An agreeing alternate parameter-space representation remains attached to the neutral coedge even when the model-space curve is preferred. A disagreeing or undecodable alternate is omitted when the model-space curve is preferred. A selected parameter-space representation that disagrees beyond the Global minimum resolution invalidates the topology candidate.

A Form 0 Curve on a Parametric Surface Entity (Type 142) stores its creation method, support-surface pointer, parameter-space curve pointer, model-space curve pointer, and preferred representation. The parameter-space curve has entity-use flag `05`. Its composition with the support surface has the same oriented model-space endpoints as the model-space curve. Projection requires every active parameter-space point to lie inside each finite declared support bound and both endpoint distances to be no greater than the Global minimum resolution. Positive-weight NURBS pcurves prove the bound by their active-range rational control hull. A parameter-preferred boundary outside a declared bound is rejected. A model-preferred boundary retains the model-space curve, omits the alternate pcurve, and records a loss. A support without retained finite bounds uses endpoint agreement only. The creation-method and preference fields are defined by [IGES 5.3 §4.32](https://paulbourke.net/dataformats/iges/IGES.pdf).

Type 141 and Type 142 model-curve pointers identify curve carriers, not Type 504 edge occurrences. Projection validates each candidate occurrence by evaluating its retained parameter interval against its start and terminate vertices. A parameter-curve collection selects a candidate only when its oriented composed endpoints agree with exactly one validated occurrence. A model-preferred item without an agreeing parameter collection selects only one validated occurrence; no collection or multiple validated occurrences do not select by edge-list order and refuse the topology candidate.

Semantic Type 141 output sets `TYPE=0` when its model-space boundary has no parameter curves and `TYPE=1` when every coedge has a parameter-curve collection; the writer refuses a mixed loop. It sets `PREF=1` because the neutral edge carrier is the authoritative trimming curve. Semantic Type 142 output sets creation method `0` because neutral IR does not identify projection, intersection, or isoparametric provenance, and sets `PREF=2` because the model-space edge carrier is authoritative while the parameter curve is accepted within the declared topology tolerance. These selected values are the IGES values defined in [IGES 5.3 §§4.31–4.32](https://paulbourke.net/dataformats/iges/IGES.pdf). The semantic Type 508 writer emits the required `ISOP` logical from explicit neutral `PcurveUse.isoparametric = Some(false)` or `Some(true)`. It refuses `None` because the missing source declaration is not false or true. The generated status values follow the four fields in [IGES 5.3 §2.2.4.4.9](https://paulbourke.net/dataformats/iges/IGES.pdf): Type 141, Type 142, Type 502, Type 508, Type 510, and Type 514 Form 1 constituent records use `00010000` (physically dependent, entity-use `00`, hierarchy `00`); Type 504 uses `00010001` (physically dependent, entity-use `00`, hierarchy `01`), as required by [IGES 5.3 §4.144.1](https://paulbourke.net/dataformats/iges/IGES.pdf), so its subordinate records retain their own display attributes; and independent geometry, Type 514 Form 2, and Type 186 use `00000000` (independent, entity-use `00`, hierarchy `00`). Type 514 Form 1 is physically dependent on its parent under [IGES 5.3 §4.147](https://paulbourke.net/dataformats/iges/IGES.pdf). Parameter-space curve entities use `00010500` (physically dependent, entity-use `05`, hierarchy `00`).

The semantic export census names every emitted standard entity type, including each physically dependent Direction Entity as `123_direction`. `unknown_entity` counts only an emitted type with no standard census mapping.

A Form 0 Trimmed Surface Entity (Type 144) stores a support-surface pointer, an outer-boundary flag, an inner-boundary count, an outer Curve on a Parametric Surface pointer, and the ordered inner Curve on a Parametric Surface pointers. When the outer-boundary flag is zero, the outer pointer is zero or omitted and the rectangular parameter domain of the support surface supplies the outer boundary. The entity then produces no explicit outer loop; each listed loop is `inner`. When the flag is one, the outer pointer is present and produces the single `outer` loop; each listed loop is `inner`.

## Appearance

Directory color zero supplies no direct color. Positive values `1` through `8` select black, red, green, blue, yellow, magenta, cyan, and white. A negative value is the negated odd Directory sequence of a Form 0 Color Definition Entity (Type 314). These standard color meanings are defined by [IGES 5.3 §2.2.4.4.13](https://paulbourke.net/dataformats/iges/IGES.pdf). Type 314 stores red, green, and blue intensities as finite percentages from `0` through `100` and an optional Hollerith name under [§4.76](https://paulbourke.net/dataformats/iges/IGES.pdf). Neutral RGBA components equal the percentages divided by `100`, with alpha `1`.

Directory line-font values `1` through `5` select standard patterns, while `0` means no pattern. A negative value is the negated odd Directory sequence of a Line Font Definition Entity (Type 304). The standard table is defined by [IGES 5.3 §2.2.4.4.4](https://paulbourke.net/dataformats/iges/IGES.pdf). Form 1 stores an orientation flag `0` or `1`, a Form 0 Subfigure Definition pointer, a positive display spacing, and a positive template scale. Form 2 stores a positive segment count, that many positive segment lengths, and exactly `ceil(count / 4)` hexadecimal digits. Pattern bits are right-justified; the unit bit describes the last segment, and unused high bits are zero. Type 304 has entity-use flag `02` and carries a standard fallback line-font value `1` through `5` in its Directory entry under [IGES 5.3 §4.70](https://paulbourke.net/dataformats/iges/IGES.pdf).

A nonnegative Directory level value selects that single exchange-file level. A negative value is the negated odd Directory sequence of a Definition Levels Property Entity (Type 406, Form 1). The property stores a positive count followed by that many distinct nonnegative level numbers. A malformed definition or link is retained but does not become a decoded display-level set.

The CADIR `display_attributes` arena preserves every signed Directory display number. It exposes a typed definition identity only when the reference graph resolves the negative pointer to an existing target admitted by the corresponding native arena: Type 304 Form 1 or 2 for a line font, Type 406 Form 1 for a definition level, or Type 314 Form 0 for a color. A missing, even-sequence, out-of-range, or wrong-type/form target leaves the typed field null and retains the signed number. The graph records one attributed `graph.pointer-unresolved` loss on the source Directory Entry. This is a CADIR projection decision; it does not replace an invalid pointer with a display default.

A positive Directory line-weight number selects that numbered increment in the uniform Global line-weight series and cannot exceed the Global maximum gradation count. Its model-space width is `number * maximum_width / maximum_gradations`; neutral/native display width converts that result to millimetres. Zero leaves the display width unspecified.

A Manifold Solid B-rep Object or orphan Shell color binds to its body. A Face color binds to that face and overrides the body color for that face. Trimmed and bounded surface colors bind to their generated sheet body and face. The blank-status field determines body visibility. Curve and surface source-object associations retain their direct Directory colors.

The `native.iges` namespace version is `2`. Its `colors` arena stores typed Type 314 percentages, names, and fallback color numbers. Its `line_fonts` arena stores typed template and visible-blank definitions. Its `definition_levels` arena stores ordered multiple-level sets. Its `display_attributes` arena stores one record per Directory entity with visibility, line-font number or definition link, level number or definition link, view, line weight, and color number or definition link. These values remain distinct from effective neutral appearance bindings.

## Byte accounting

The Fixed ASCII reader retains every physical card and every Directory/Parameter entity in `native.iges`, including typed domain arenas where projected and generic entity records otherwise. Card payloads, line endings, Directory fields, Parameter tokens, links, and source identities remain available through that namespace. `SourceFidelity` retains the complete source image as a byte record and records its document-local SHA-256 digest. The reader emits a closed `transfer_ledger` for every non-null Directory entity and verifies it against the decoded model.

## Decode admission

Semantic decode is bounded by the caller's `DecodePolicy`. The policy limits
input bytes, temporary materialization, retained bytes, admitted entities,
collection items, recursive depth, and algorithm work. File-declared counts,
pointer walks, recursive definitions, and geometric recovery cannot override
these limits. A refused request returns a structured resource refusal and does
not return a partial semantic document.

Under the service policy, the absolute ceilings are 256 MiB of input, 512 MiB
of temporary materialization, 512 MiB of retained decode data, 8,000,000
entities, 1,000,000 collection items, depth 128, and 256,000,000 work units.
The desktop policy permits 4 GiB of input, 4 GiB of temporary materialization,
4 GiB of retained decode data, 64,000,000 entities, 16,000,000 collection
items, depth 256, and 4,000,000,000 work units. The policy is implementation
admission control; no IGES field changes it.

A successful semantic decode has no error-severity neutral-validation finding.
The reader validates referential integrity, geometry domains, topology
ownership, endpoint agreement, pcurve agreement, transforms, and document
invariants before it returns the document. A failed candidate does not commit
partial topology.

Every non-null Directory Entry has one retained native identity and one
`transfer_ledger` disposition. A supported entity without neutral projection
has a stable namespaced loss code, source provenance, and its retained native
record. A projected entity with reduced fidelity records the reduction on the
same source identity. Salvage mode returns warning losses; strict mode refuses
any warning-or-higher loss before returning a semantic result.
