# IGES 5.1/5.2/5.3 format specification

Record offsets, field widths, and endianness are also maintained as a machine-checked table in [`docs/layouts/iges.md`](../layouts/iges.md), generated from `docs/layouts/iges.toml`. That table is the canonical source for the numbers; the prose below carries the semantics. `cargo test -p cadmpeg --test layout_tables` proves the two agree.

## Physical representation

The representation flag is in the first 80 bytes. A `C` in byte 73 identifies Compressed ASCII. The other bytes of its flag record are printable ASCII. An `S` in byte 73 identifies Fixed ASCII.

The Binary representation starts with one 80-byte Binary Flag Section. Byte 1 is ASCII `B`. Bytes 2 through 5 are the big-endian unsigned 32-bit value `75`, which is the count of the remaining flag bytes. Bytes 6 through 11 are the one-byte bit lengths `Is`, `Id`, `NXs`, `NFs`, `NXd`, and `NFd`. Bytes 12, 17, 22, 27, 32, and 37 are ASCII `B`, `S`, `G`, `D`, `P`, and `T`. Each letter is followed by a big-endian unsigned 32-bit displacement for that section. Bytes 42 through 72 are unassigned. Byte 73 is ASCII `B`, bytes 74 through 79 are ASCII blanks or zeroes, and byte 80 is ASCII `1`. The Binary Flag Section contains no control bytes.

The Fixed ASCII representation is an ordered sequence of physical lines. A canonical line contains an 80-byte card followed by a line ending. Card bytes 1 through 72 are section data. Byte 73 is the section marker. Bytes 74 through 80 are the right-aligned decimal sequence field. Parameter Data cards instead use bytes 65 through 72 for the right-aligned Directory Entry back-pointer, byte 73 for the `P` marker, and bytes 74 through 80 for the Parameter Data sequence.

Byte positions are one-based in this specification. Source spans use zero-based half-open byte ranges. Parsing records the card payload and line ending as disjoint source spans before interpreting fields. A short card, bytes beyond column 80, a noncanonical line ending, and bytes after the Terminate card remain separate physical records with their original spans.

The canonical section order is Start (`S`), Global (`G`), Directory Entry (`D`), Parameter Data (`P`), and Terminate (`T`). Section sequences are positive decimal integers starting at one and increasing by one within each section. A Directory Entry occupies two consecutive `D` cards. Its first card has an odd sequence and its second card has the following even sequence. Directory pointers refer to the odd Directory Entry sequence. Zero is a null pointer where the owning field permits null.

The Terminate data area contains four eight-byte fields: `S` plus the seven-digit Start count, `G` plus the seven-digit Global count, `D` plus the seven-digit Directory Entry card count, and `P` plus the seven-digit Parameter Data card count. The remaining data area is blank.

## Global section

The Global data stream is the concatenation of bytes 1 through 72 from its cards. Its first value defines the parameter delimiter and its second value defines the record delimiter. Each is a one-character Hollerith string. Omitted first and second values select comma and semicolon respectively.

A Hollerith value is an unsigned decimal byte count, the byte `H` or `h`, and exactly that many following bytes. Delimiters inside the counted payload are data. The count and payload may cross card boundaries. Integer values are signed decimal integers. Real values accept a decimal point and an exponent introduced by `E`, `e`, `D`, or `d`. An empty or blank-only field between delimiters is omitted. The record delimiter terminates the Global record.

Global string values use printable seven-bit ASCII bytes (`0x20` through `0x7e`). A string cannot contain an ASCII control byte (`0x00` through `0x1f` or `0x7f`) or a byte with its high bit set. A space, parameter delimiter, or record delimiter inside a counted payload is string data. Global string values are not UTF-8 text ([IGES 5.3 §2.2.2.3](https://paulbourke.net/dataformats/iges/IGES.pdf)).

An IGES real is a sending-system approximation. A `D` or `d` exponent selects the Global double-precision significance; every other real spelling selects the Global single-precision significance. For a nonzero real value `x` with `p` declared significant digits, its representation uncertainty is `0.5 × 10^(floor(log10(abs(x))) - p + 1)`. Zero and integer tokens have zero representation uncertainty. Two redundant numeric fields agree when their absolute difference is no greater than the sum of their representation uncertainties.

Global fields declare the sender and receiver identifiers, native file name, generator, significant digits, single and double precision limits, model scale, units flag and unit name, maximum line-weight gradation and width, creation and modification timestamps, minimum resolution, maximum coordinate, author, organization, specification version, drafting standard, and application protocol. The single-precision and double-precision significance fields are required positive integers representable as `u32`. An omitted model scale defaults to `1.0`, an omitted units flag defaults to inches (`1`), an omitted maximum line-weight gradation count defaults to `1`, and an omitted specification version flag defaults to IGES 2.0 (`3`). A supplied value must have its declared lexical type; an unparseable supplied value does not select a default. The model scale and maximum line width are finite and positive. The line-weight gradation count is in `1` through `32768`.

Global field 19, Minimum User-Intended Resolution, is required and has no default. It is the smallest distance between coordinates, in model-space units, that the receiving system considers discernible ([IGES 5.3 §2.2.4.3.19](https://paulbourke.net/dataformats/iges/IGES.pdf)). A finite nonnegative value is valid. An omitted, negative, or nonfinite value is malformed. For a positive value, the source rule treats coordinate locations at a distance strictly less than the value as coincident. CADIR decision: zero uses exact coordinate equality because no positive distance is less than zero. Every Global-resolution coordinate comparison uses this strict-positive, exact-zero predicate. The independent coordinate-precision quantum remains available for topology sewing when it is larger than the Global resolution.

A generated file declares the largest positive finite edge or vertex tolerance, with a lower bound of `0.01` millimetres equal to the writer's pcurve-coincidence tolerance. Semantic output uses millimetres with model scale one. Its generation timestamp is the current UTC time. Its maximum-coordinate value is an exact upper bound when every emitted coordinate-bearing entity has a bounded encoding that the writer can evaluate; otherwise it is zero, meaning unspecified. Sender, file name, generator, author, and organization identify the generated artifact and the codec rather than copied source metadata.

Global field 14 values `1` through `11` select inches, millimetres, other named units, feet, miles, metres, kilometres, mils, microns, centimetres, and microinches; an omitted field defaults to `1` ([IGES 5.3 §2.2.4.3.14](https://paulbourke.net/dataformats/iges/IGES.pdf)). Postprocessors use field 14 unless its value is `3`. For a value other than `3`, field 15 is redundant and an inconsistent value is ignored; the exact table payloads are `IN`, `INCH`, `MM`, `FT`, `MI`, `M`, `KM`, `MIL`, `UM`, `CM`, and `UIN` ([IGES 5.3 §2.2.4.3.15](https://paulbourke.net/dataformats/iges/IGES.pdf)). When field 14 is `3`, field 15 names the desired unit and shall conform to MIL-STD-12 or IEEE 260; IGES 5.3 delegates that name space and does not define a closed alias list. CADIR decision: the codec retains any nonempty flag-3 name during inspection. Semantic projection proceeds only when the exact name has a known millimetre factor; otherwise decode refuses before coordinate projection. Length-valued fields are converted from the declared units and model scale only when projected to neutral IR. Native values remain unchanged. The specification version field is `9` for IGES 5.1, `10` for IGES 5.2, and `11` for IGES 5.3.

Semantic output for IGES 5.1 and 5.2 uses the same emitted entity and form set except that neither version defines the open Shell Entity Type 514 Form 2. IGES 5.3 admits that form. Selecting 5.1 or 5.2 for a model that requires an open shell refuses the write before any bytes are produced. Closed-shell manifold B-rep Types 186 and 502 through 514 Form 1 and pointer-defined analytic surface Types 190 through 198 are available in all three targets.

Semantic output represents a plane as the parameterized Plane Surface Type 190 Form 1. A circular cylinder, circular cone, sphere, or torus that supports B-rep topology uses its exact B-rep analytic entity Type 192, 194, 196, or 198 with physically dependent Point Type 116 and Direction Type 123 entities. These analytic entities retain the unbounded carrier and its parameter frame without rational conversion. Types 192 through 198 are B-rep surface entities and are not emitted as standalone or trimmed-surface carriers. A non-B-rep analytic surface has no finite parameter bounds in neutral IR from which to construct an equivalent Type 128 patch, so semantic output refuses it before producing bytes. This refusal has no loss note because no output representation is selected.

Generated analytic frames accept normalized axis dot-product residuals through `1e-6`. The writer keeps the primary axis, removes its component from the reference axis, normalizes the repaired reference, and derives the third axis by a right-handed cross product. A placement's supplied third axis must have the same handedness and a cross-product residual through `1e-6`. Larger skew is malformed and is refused before output. The repair bound is a writer convention for finite-precision neutral frames, not an IGES file tolerance.

Global Hollerith payloads retain their exact source bytes in the source image and physical-card arena. CADIR decision: inspection reports invalid string fields without treating them as text. Container-only decode retains a structurally framed Global record even when a string byte violates the ASCII rule. A valid Global string becomes text in its source attribute. An invalid sender-product, native-file-name, or units-name payload becomes `sender_product_bytes_hex`, `native_file_name_bytes_hex`, or `native_units_bytes_hex` with lowercase hexadecimal bytes. Semantic decode refuses before Directory Entry or Parameter Data projection when any Global string contains a non-printable or non-ASCII byte; it does not replace or ignore that byte.

## Directory Entry section

Each Directory Entry contains twenty fixed eight-byte fields across two cards. Blank numeric fields have their field-defined default. Nonblank numeric fields are right-aligned signed decimal integers.

The first card fields are entity type, Parameter Data start sequence, structure, line font pattern, level, view, transformation matrix, label-display associativity, and the eight-character status number. The second card fields are the repeated entity type, line weight, color, Parameter Data card count, form number, two reserved fields, entity label, and entity subscript. The repeated entity type must equal the first-card value. Reserved bytes are retained whether blank or nonblank.

The status number is one eight-digit decimal integer interpreted as four two-digit fields: blank status, subordinate-entity switch, entity-use flag, and hierarchy. An entirely blank status field is defaulted to four zero fields under [IGES 5.3 §2.2.2](https://paulbourke.net/dataformats/iges/IGES.pdf) and [§2.2.4](https://paulbourke.net/dataformats/iges/IGES.pdf). An explicit status value fills all eight columns with ASCII digits; [§2.2.4.4.9](https://paulbourke.net/dataformats/iges/IGES.pdf) forbids spaces, including leading and trailing spaces. A nonnegative Structure value is ignored. A negative Structure value is permitted only for Type 422 Forms 0 and 1, Type 402 Forms 5001 through 9999, and macro-instance types 600 through 699 or 10000 through 99999. Type 422 points to Type 322 Form 0. An implementor-defined Type 402 points to Type 302 with the same form number. A macro instance points to Type 306 or to a Type 416 external reference for a library definition. Other negative structure, line-font, level, view, transformation, label-display, or color values denote Directory Entry pointers where their fields permit an entity reference. Pointer parity and source-specific target type are validated after all entries are indexed.

Subordinate-entity switch `00` is independent, `01` is physically dependent, `02` is logically dependent, and `03` is both physically and logically dependent. A rule that requires physical dependence accepts `01` and `03`. A rule that requires logical dependence accepts `02` and `03`.

## Parameter Data section

Bytes 1 through 64 of Parameter Data cards form parameter fragments. Bytes 65 through 72 identify the owning odd Directory Entry sequence. Zero, an even sequence, and an absent Directory Entry sequence are invalid back-pointers. Fragments are grouped by that back-pointer and ordered by Parameter Data sequence. The Directory Entry Parameter Data start sequence and card count define the exact contiguous range. Every card in that range has the owning Directory Entry sequence, and no card outside the range has that owner. A disagreement is malformed input. A record delimiter terminates the entity's primary parameters.

Tokens retain their exact source spans and lexical bytes. Token classes are integer, real, Hollerith string, Directory Entry pointer, omitted value, parameter delimiter, record delimiter, and retained uninterpreted value. The type number is the first Parameter Data field and precedes Index 1. An empty or blank-only Parameter Data field is an omitted value. A required-default integer or real field uses its defined explicit default or the data-type default zero. A logical field defaults to false. A string field defaults to the null string. A pointer field defaults to zero only when its entity field defines zero or default semantics. Count fields and non-null constituent pointers are required-no-default fields. A supplied token must have the field's lexical type; a wrong-typed token does not select a default. A record delimiter supplies every remaining trailing required-default field. Entity accessors impose field-specific token types and arity. Pointer interpretation is field-specific; a numeric token is not globally coerced to a pointer. [IGES 5.3 §§2.2.4.5.1–2](https://paulbourke.net/dataformats/iges/IGES.pdf)

Semantic output writes every nonzero real with 17 significant decimal digits and a `D` exponent, declares 17 double-precision significant digits in Global field 8, and writes either sign of zero as `0`. This spelling round-trips every finite binary64 value without flushing small nonzero values to zero. Generated Parameter Data cards end immediately after a parameter or record delimiter. A generated token longer than the 64-byte Parameter Data area is refused. Card boundaries have no token semantics on input; delimiter-aligned output is an interoperability convention.

A semantic edge parameter range has a finite start strictly less than its end. A zero-length range is a degenerate edge and is refused; it is never promoted to a revolution. An unreferenced circle or ellipse uses one complete revolution. A referenced circular or elliptical edge whose model-space start and end points are identical is also complete. Generated complete Type 100 and Type 104 arcs copy the two start-coordinate tokens to the terminate coordinates byte for byte.

A declared count applies only when the complete counted sequence fits before the end of the entity-specific parameters. Fixed-width items require `count * width` tokens. If a nested counted sequence is incomplete, its declared count remains present, its typed item list is empty, and no later token is reinterpreted as the start of a sibling item. Every counted native record retains its declared count separately from its typed items. Type 402 Forms 9, 13, 16, 18, 20, and 21 retain their child, geometry, entity, flow, connection, join, name, name-display, and continuation counts as applicable.

After all specified or defaulted entity parameters, and before the record delimiter, an entity may carry an ordered associativity pointer group and an ordered property pointer group. Each group begins with a count followed by that many pointers. The entity type/form parameter table defines the last entity parameter number `NV`; the first trailing count is `NA` at `NV+1`. Either group may be empty or defaulted. The complete trailing groups remain part of the owning entity and retain token spans. [IGES 5.3 §2.2.4.5.2](https://paulbourke.net/dataformats/iges/IGES.pdf)

Type 116 Form 0 lists `X`, `Y`, and `Z` at indexes 1 through 3 and an optional display-symbol pointer `PTR` at index 4 under [IGES 5.3 §4.16](https://paulbourke.net/dataformats/iges/IGES.pdf). Because optional fields do not occur in free-formatted sections, this trailing optional field is represented as a required-default field under [§2.2.1](https://paulbourke.net/dataformats/iges/IGES.pdf): when a pointer group follows, `PTR` is an explicit zero or an omitted field, so `NV=4` and `NA` is token index 5. A record delimiter immediately after `Z` defaults `PTR`, `NA`, and `NP` under [§2.2.3](https://paulbourke.net/dataformats/iges/IGES.pdf), so no trailing group is present. A property-only suffix contains explicit `NA=0` before `NP`; an association-only suffix may omit `NP` at the record delimiter, which defaults it to zero.

## Entity graph

The entity identity is its odd Directory Entry sequence. Graph construction indexes all identities before resolving references. Each pointer evaluation has resolved, null, dangling, out-of-range, even-sequence, wrong-type, or cyclic resolution. A zero pointer has null resolution and creates no edge because it specifies no relationship; the raw zero remains in the native Directory Entry record. Each edge records the source entity, source field or parameter index, raw pointer, expected target class, and non-null resolution state. A value that cannot identify a Directory Entry because its sign or magnitude is invalid has out-of-range resolution. Each unresolved edge is a `reference_graph_not_closed` loss with the source Directory Entry identity and byte offset. Transformation links compose recursively and a transformation cycle has cyclic resolution. The other Directory Entry links select definitions or display entities and do not compose into same-kind reference chains.

Parameter Data pointer sign interpretation is field-specific. A positive pointer uses its value as the Directory Entry sequence. A field that defines a negative pointer encoding uses the negated magnitude and retains the signed raw value. A nonzero candidate resolves only if its sequence fits `u32`, is odd, identifies an existing Directory Entry, and satisfies the field's entity-type, form, and Directory-status target class. Only a resolved parameter pointer creates a typed arena identity. An unresolved parameter pointer leaves the typed arena field null and remains a reference edge. Its loss offset identifies the first byte of the source parameter token.

An entity retains its type, form, Directory Entry fields, status fields, ordered parameter tokens, trailing association and property groups, source spans, and reference edges. Unsupported type/form pairs remain named native records and prevent any support claim whose closed envelope admits the pair.

## Units and transformations

Model-space lengths equal native values divided by the Global model-space scale and converted from the declared unit to millimetres. Dimensionless values, parameter coordinates, weights, and unit direction vectors are not length-scaled. Angles convert to radians when projected to neutral IR. A transformation matrix is a 3-by-3 linear part plus translation. Translation is length-valued. Entity transforms compose from the entity definition toward model space exactly once. Definition, subfigure-instance, and occurrence transforms remain separate native relationships.

## Geometry

CADIR decision: resource ceilings bound semantic materialization and recovery work. They are not IGES validity rules. A Type 112 projection accepts at most 100,000 segments (`iges_spline_segments`); a Type 106 projection accepts at most 1,000,000 tuples (`iges_copious_tuples`); a Type 102 projection accepts at most 100,000 direct children (`iges_composite_children`); a Type 114 projection accepts at most 1,000,000 poles (`iges_spline_surface_poles`); and a Type 128 projection or Type 120 surface of revolution accepts at most 1,000,000 poles (`iges_surface_poles` or `iges_revolution_poles`). A request above one of these per-entity bounds returns a terminal `CodecError::ResourceLimit` before the corresponding semantic allocation. It does not return a partial neutral result.

The Type 124 transformation-chain and Type 102 composite-carrier walks use the smaller of their codec ceiling and `DecodePolicy.max_recursion_depth`, with a codec ceiling of 64. Transformation-chain overflow returns a terminal `CodecError::ResourceLimit` with dimension `Codec("iges_transform_depth")`. Composite-carrier overflow fuses the decode session and returns a terminal `CodecError::ResourceLimit` with dimension `Codec("iges_composite_depth")`. `MAX_COMPOSITE_DEGREE = 1024` is a representation ceiling for synthesized carrier degree, not a resource limit; when degree elevation cannot satisfy it, the ordered native Type 102 carrier is retained and loss `curve.composite-carrier-degraded` is emitted.

Form 63 validation uses one local slice of at most 20,000,000 pair-work units. If this slice is exhausted under the session allowance, the native Type 106 record is retained and loss `entity.not-projected` is emitted. Product occurrence expansion uses local output and nesting ceilings of 100,000 records and 64 levels, each lowered by `DecodePolicy.max_collection_items` and `DecodePolicy.max_recursion_depth`; local truncation retains the native expansion record and emits `occurrence.expansion-output-truncated` or `occurrence.expansion-depth-truncated`. Session-wide exhaustion of an applicable input-byte, materialized-byte, retained-byte, entity, collection, recursion, or work allowance returns a structured `CodecError::ResourceLimit`; a file-declared count cannot raise a CADIR limit.

Type 116 Form 0 stores one finite model-space point. Type 123 Form 0 stores three finite dimensionless direction components and is physically dependent. Type 108 Form 0 stores a plane through the origin of its Directory transformation with local X and Y axes from that transformation; its local Z axis is the plane normal.

Type 124 Forms 0 and 1 define right-handed and left-handed affine transformations. Each linear coefficient has the representation uncertainty of its own real token. Interval arithmetic propagates those uncertainties through column norms, column dot products, and the determinant. A valid linear part has `1` in every column-norm interval, `0` in every distinct-column dot-product interval, and the form's required determinant (`+1` for Form 0 or `-1` for Form 1) in its determinant interval. Arithmetic interval bounds are rounded outwards. After these invariants hold, the decoder canonicalizes the rounded linear coefficients to an orthonormal frame and preserves the three translation coefficients. Nested transformations compose those canonical frames.

A declared unit vector is valid when its component uncertainty intervals produce a squared-norm interval that contains `1`. Two declared vectors are orthogonal when the interval of their dot product contains `0`. These rules apply to primitive axes, solid sweep axes, Type 130 offset-plane normals, and Type 140 offset indicators. A geometric vector that is used after validation is normalized before it defines a neutral direction.

Pointer-defined analytic surfaces use odd Directory pointers to Type 116 location points and physically dependent Type 123 direction entities. A referenced Type 123 entity has Form 0, has no transformation matrix, has three numeric finite components, and defines a nonzero vector. Type 190 Forms 0 and 1 define a plane from a location and normal, with Form 1 adding a reference direction. Type 192 Forms 0 and 1 define a circular cylinder from a location, axis, positive radius, and a Form 1 reference direction. Type 194 Forms 0 and 1 define a circular cone from a location, axis, nonnegative radius, semi-angle in degrees in `(0, 90)`, and a Form 1 reference direction. Type 196 Forms 0 and 1 define a sphere from a center and positive radius, with Form 1 adding its polar axis and reference direction. Type 198 Forms 0 and 1 define a torus from a center, axis, positive major and minor radii satisfying `minor < major`, and a Form 1 reference direction. Form 0 derives a stable perpendicular frame from the axis. Each Form 1 reference direction must resolve. It is projected into the plane normal to the axis and must remain nonzero.

Type 130 Form 0 defines a planar offset of a base curve. FLAG `1` uses one uniform distance, `2` interpolates two distances as a function of arc length or native parameter, and `3` takes one coordinate of another curve as the distance function. A real or integer parameter that is unused for the selected FLAG is zero or omitted; omission selects that data type's implicit zero. The unused DE2 pointer is an explicit integer zero because pointer fields have no implicit default unless their field definition declares one.

Type 106 interpretation flag IP and Directory form are redundant required constraints. Forms 1, 11, 20, 21, 31 through 38, 40, and 63 require IP `1` for planar coordinate pairs with one common Z value. Forms 2 and 12 require IP `2` for coordinate triples. Forms 3 and 13 require IP `3` for point-and-vector sextuples. A disagreement is malformed entity data; IP determines tuple width but does not override the Directory form's entity semantics.

Type 106 Forms 11 through 13 define linear paths parameterized from zero through `N - 1`, with one unit parameter interval per consecutive point pair ([IGES 5.3 §§4.6–4.7](https://paulbourke.net/dataformats/iges/IGES.pdf)). The source order is the curve order. Segments may cross or coincide, so consecutive duplicate points remain zero-length segments in the ordered path. Form 63 defines a simple closed planar path in definition-space XY ([IGES 5.3 §§4.11, 4.68](https://paulbourke.net/dataformats/iges/IGES.pdf)). Its first and last points are coincident under the Global-resolution predicate. The first/last pair is the only repeated point permitted; every other pair of points must be noncoincident. Consecutive segments may meet only at their shared intermediate endpoint, and nonconsecutive segments may not intersect or overlap except that the first and last segments may meet at the closure endpoint. Form 63 checks these geometric intersections in definition-space XY before applying the entity transformation. The projected Form 63 edge uses one shared endpoint vertex. The edge and vertex carry the positive Global minimum resolution as their topology tolerance. The coordinate coincidence rule is a CADIR application of Global field 19; the exact segment-intersection rule follows the simple-closed-curve constraint.

Type 102 Form 0 defines a continuous, directed curve as an ordered list of physically dependent point, connect-point, and parameterized-curve entities ([IGES 5.3 §4.4](https://paulbourke.net/dataformats/iges/IGES.pdf)). The source rule requires the terminate point of each constituent curve to have the same coordinates as the start point of the succeeding curve. CADIR applies the Global-resolution predicate to this coordinate agreement: a positive resolution admits only a distance strictly less than the value, and zero requires exact coincidence. The neutral exact carrier concatenates the bounded child carriers in source order. If a child has no bounded carrier, two adjacent endpoints are not coincident under the predicate, or the concatenated carrier cannot be evaluated over a nonempty range, the decoder retains the ordered native composite carrier and records a geometry loss. This documented salvage is a CADIR decision under the conformance rule that permits an implementation to ignore an unprocessable entity or its complete multi-entity structure ([IGES 5.3 §1.4.4.1](https://paulbourke.net/dataformats/iges/IGES.pdf)).

Curve parameters use the entity-defined native domains. Type 100 uses the absolute definition-space angle from the positive X axis, with the terminate angle increased by one turn when required by counterclockwise order. Type 102 starts at zero and gives each constituent curve a span equal to its native terminate parameter minus its native start parameter. Type 104 uses the default ellipse, parabola, or hyperbola parameterization defined by its coefficients and endpoint coordinates. Type 106 Forms 11 through 13 and Form 63 use `[0, N - 1]`. Type 110 Forms 0, 1, and 2 use `[0, 1]`, `[0, infinity)`, and `(-infinity, infinity)`. Type 112 uses `[T(1), T(N+1)]`. Type 126 uses `[V(0), V(1)]` inside `[T(0), T(N)]`. Type 130 uses `TT1` through `TT2` inside the native domain of its base curve ([IGES 5.3 §§4.3–4.5, 4.7, 4.13–4.14, 4.23, 4.25](https://paulbourke.net/dataformats/iges/IGES.pdf)).

CADIR preserves these native ranges in exact spline, path, NURBS, and composite carriers. Primitive carriers use an exact equivalent neutral parameter when their IR evaluator requires it: a bounded Type 110 line uses distance `[0, length]`, a Type 100 circle starts at zero with its reference direction at the source start point, and Type 104 parabola and hyperbola carriers use their canonical IR parameters. Type 110 Form 2 is an exact infinite line carrier without a finite edge range. Type 110 Form 1 has no neutral ray carrier; it remains in the native entity arena and produces `entity.not-projected`. Type 130 maps `TT1`, `TT2`, and parameter-basis distance controls into the selected neutral carrier. Exact Type 130 projection currently admits Type 100, Type 110, and nested Type 130 base mappings. A base parameterization without an exact mapping remains in the native entity arena and produces `entity.not-projected`; CADIR does not invent a finite fallback range.

Type 104 defines a nondegenerate ellipse, hyperbola, or parabola in an XY-parallel plane ([IGES 5.3 §4.5](https://paulbourke.net/dataformats/iges/IGES.pdf)). Standard position requires each conic axis to be parallel to X or Y and centers the conic on the Z axis; a parabola has its vertex on that axis. An axis-aligned parabola may open along X or Y. A Directory Type 124 transformation moves the standard-position conic into model space. Forms 1, 2, and 3 identify ellipse, hyperbola, and parabola, but the form is informational; the coefficients determine the conic family. Form 0 is the deprecated unspecified form. The default ellipse parameter is `C(t) = (a cos(t), b sin(t), ZT)` with `0 <= t1 < 2*pi` and `0 <= t2 - t1 <= 2*pi`. The default parabola parameter is the signed coordinate on its opening axis, with the other coordinate from the coefficient-defined quadratic. The default hyperbola parameter satisfies `C(t) = (a sec(t), b tan(t), ZT)` on one branch with `-pi/2 < t1,t2 < pi/2`; axis orientation selects the corresponding sign and coordinate arrangement. The start and terminate points select `t1` and `t2`.

The six coefficients define the analytic parent conic and the endpoint fields define the ordered start and terminate coordinates; neither data set replaces the other. After units, model scale, and the Type 124 transformation are applied, each listed endpoint must be at a Euclidean distance strictly less than the positive Global field 19 value from the coefficient-defined carrier evaluated at its selected parameter ([IGES 5.3 §2.2.4.3.19](https://paulbourke.net/dataformats/iges/IGES.pdf)). Zero requires exact equality. The accepted endpoint coordinates remain the neutral topology vertices while the coefficients define the neutral carrier. CADIR decision: if either endpoint fails this predicate, the decoder retains the native Type 104 record and records `entity.not-projected`; it does not replace the endpoint with the evaluated carrier point.

Type 126 has positive weights and a nondecreasing knot vector under [IGES 5.3 §§2.2.4.3.9–2.2.4.3.11, 2.2.4.3.19, 4.23, and Appendix B §B.4](https://paulbourke.net/dataformats/iges/IGES.pdf). Directory Form Number 0–5 records a preferred analytic type; it does not change the Type 126 parameter interpretation or carrier. The four property flags are consistency claims about the serialized values, not alternate geometry definitions. `PROP1 = 1` requires the transformed control-point curve to fit the declared plane and the final three fields to contain a declared unit normal; those fields shall exist and are ignored when the curve is nonplanar. `PROP1 = 0` is required for a nonplanar curve. CADIR treats a degenerate carrier whose control points do not determine one unique normal as a containing-plane case and still checks its declared normal when `PROP1 = 1`. `PROP2 = 1` exactly when evaluating the active-range endpoints at `V(0)` and `V(1)` gives a distance of zero or a value strictly less than the Global minimum resolution; otherwise it is `0`. `PROP3 = 1` is required when all positive weights agree within their declared real representation uncertainty; the projected polynomial omits weights because their common factor cancels. `PROP3 = 0` requires unequal positive weights and preserves them. `PROP4` records periodicity but is informational: it does not replace the coefficient-defined carrier or alter its evaluation. A contradictory `PROP1`, `PROP2`, or `PROP3` is invalid; CADIR retains the native record and emits `entity.not-projected`. The active parameter range satisfies `T(0) <= V(0) < V(1) <= T(N)`. A declared range endpoint outside its active knot bound by no more than the combined representation uncertainty is clamped to that bound. A larger disagreement is invalid.

Type 112 defines each segment coordinate as `a + b*w + c*w^2 + d*w^3`, where `w = u - T(i)`. The uncertainty interval for `w` is the interval of `T(i+1) - T(i)`. Interval arithmetic propagates the breakpoint and coefficient uncertainties through `w`, `w^2`, and `w^3`. The terminal-position interval of each segment must overlap the next segment's `a` interval in every coordinate. For `NDIM = 2`, each `BZ`, `CZ`, and `DZ` interval must contain zero. The final twelve values are redundant evaluations of the last polynomial and its first three factorial-scaled derivatives. A disagreement between their intervals and the evaluated coefficient intervals produces a loss but does not replace or discard the coefficient-defined curve.

IGES defines angular quantities and their parameter domains but no angular equality tolerance ([IGES 5.3 §§4.3–4.5, 4.13](https://paulbourke.net/dataformats/iges/IGES.pdf)); its geometric coincidence rule is the linear Global minimum resolution. CADIR decision: curve and surface projection and semantic conic writing use one absolute angular slack of `2π × 10^-12` radians for floating-point normalization. An arc whose endpoint directions differ by no more than this slack is normalized as a complete turn. A revolution whose sweep exceeds `2π` by no more than this slack is accepted and clamped to `2π` before exact carrier construction. This slack is implementation policy, not an IGES entity tolerance, and does not replace Global-resolution checks for coordinates.

## Topology

Manifold solid B-rep entities preserve source vertex, edge, loop, face, shell, and solid identity. Edge uses reference shared edge identity; loop orientation and face same-sense fields determine coedge and face orientation. A solid region's ordered shell list stores the exterior shell first and every void shell afterward. Type 186 writes the first shell as `SHELL` and the remaining shells as its ordered void list.

Every use of one Edge List item in a shell belongs to one cyclic radial ring. A closed Form 1 shell requires exactly two opposite-sense uses per edge. An open Form 2 shell preserves one, two, or more uses without imposing the closed-manifold cardinality rule; rings with more than two uses represent explicit non-manifold sharing.

A Form 1 Edge List Entity (Type 504) stores a positive ordered list of model-space curve pointers and one-based start and end indices into Form 1 Vertex List entities. Evaluating the curve at its stored parameter interval endpoints must be coincident with the referenced vertex points under the Global-resolution predicate. An inconsistent edge prevents attachment of every topology candidate that consumes it.

A Form 1 Loop Entity (Type 508) stores a positive ordered use count. Each use selects an Edge List or Vertex List item, stores an orientation logical, and stores an arbitrary ordered sequence of `(ISOP, CURV)` parameter-curve pairs. Edge uses become coedges. Vertex uses become pole uses positioned after the preceding edge use in cyclic loop order, or the sole unanchored use of a vertex-only loop. Every parameter curve remains ordered and retains its isoparametric logical. The parameter-curve collection forms one connected parameter-space image. Composing its first endpoint, adjacent joins, and final endpoint with the face surface must be coincident with the oriented edge vertices under the Global-resolution predicate. A pole-use collection has the same endpoint contract with the pole vertex. Disagreement prevents attachment of the containing topology candidate.

A Form 1 Face Entity (Type 510) stores a support-surface pointer, a positive loop count, an outer-loop logical, and the ordered loop pointers. When the logical is true, the first loop is `outer` and every following loop is `inner`. When it is false, every loop is `inner` and the support surface's parameter domain supplies the exterior boundary. A face has at most one explicit outer loop. When neutral IR does not classify a loop, the writer uses the first unclassified loop as the explicit outer loop; an explicitly classified outer loop takes precedence.

Boundary and curve-on-surface entities are valid independent entities and do not require a bounded-surface or trimmed-surface owner. When a bounded-surface or trimmed-surface entity consumes them, they carry face-local boundaries and produce sheet regions whose loops, coedges, edges, and vertices are owned by the source face. No cross-face edge sharing is inferred without a shared source topology entity. A topology candidate is attached only after the complete neutral ownership and reference graph validates. A failed topology candidate records a loss only on its owning bounded-surface or trimmed-surface entity.

Face-local carrier agreement uses the Global-resolution predicate in model units. Boundary-ring closure and face-local vertex merging use a topology sewing tolerance equal to the larger of the Global minimum resolution and one coordinate quantum at the largest absolute endpoint coordinate, where the quantum follows the Global single-precision significant-digit count; the sewing comparison uses the same strict-positive, exact-zero predicate. The resulting vertices, edges, and face store that sewing tolerance. Exact conversion of a source parameter curve to neutral NURBS geometry has no fit tolerance; the Global resolution is not recorded as an approximation bound.

Declared surface parameter bounds remain attached to the exact procedural surface construction. Type 118 retains the two rail intervals in rail order. Type 120 retains the generatrix interval and the angular interval. Type 122 retains the directrix interval. Type 128 retains its increasing `[U(0), U(1)]` and `[V(0), V(1)]` subranges both as ordered exact-surface parameters and as record bounds. A Type 128 bound outside its active knot domain by no more than its declared real representation uncertainty is clamped to the domain endpoint. A larger disagreement, an empty interval, or a permutation of the four range fields is invalid.

Type 140 evaluates the oriented unit normal of its support at `(Um, Vm)`. A support with four finite parameter bounds uses the midpoint of each interval; an unbounded support uses `(0, 0)`. The declared offset indicator must agree, within its real representation uncertainty, with that normal or its negation. Agreement selects positive support-normal distance; negation selects negative support-normal distance. An arbitrary unit vector is not an offset indicator. The indicator selects the sign only and does not replace the varying normal field used to evaluate the offset.

A Form 0 Boundary Entity (Type 141) stores `TYPE`, `PREF`, the support-surface pointer, and a positive model-curve count. Each ordered model-curve item stores its curve pointer, sense (`1` forward or `2` reversed), pcurve count, and that many parameter-curve pointers. `TYPE=0` requires every pcurve count to be zero. `TYPE=1` requires every pcurve count to be positive. The parameter curves of one item remain ordered and together form that coedge's parameter-space image.

Type 141 `PREF=1` selects the model-space trimming curves for neutral topology. Values `0`, `2`, and `3` select the parameter-space collections when present and require their composed endpoints to be coincident with the model-space curves under the Global-resolution predicate. Type 142 reverses the numeric preference roles: `PREF=1` selects the composed parameter-space curve, `PREF=2` selects the model-space curve, and values `0` and `3` use both equally. An agreeing alternate parameter-space representation remains attached to the neutral coedge even when the model-space curve is preferred. A disagreeing or undecodable alternate is omitted when the model-space curve is preferred. A selected parameter-space representation that is not coincident under the Global-resolution predicate invalidates the topology candidate.

A Form 0 Curve on a Parametric Surface Entity (Type 142) stores its creation method, support-surface pointer, parameter-space curve pointer, model-space curve pointer, and preferred representation. The parameter-space curve has entity-use flag `05`. Its composition with the support surface has the same oriented model-space endpoints as the model-space curve. Projection requires both endpoint pairs to be coincident under the Global-resolution predicate; disagreement prevents attachment of the containing topology candidate.

Semantic Type 141 output sets `PREF=1` because the neutral edge carrier is the authoritative trimming curve. Semantic Type 142 output sets creation method `0` because neutral IR does not identify projection, intersection, or isoparametric provenance, and sets `PREF=2` because the model-space edge carrier is authoritative while the parameter curve is accepted within the declared topology tolerance. Generated Type 502, 504, 508, 510, and 514 constituent topology entities use subordinate switch `01` and hierarchy `00`. Type 504 has no distinct hierarchy policy.

The semantic export census names every emitted standard entity type, including each physically dependent Direction Entity as `123_direction`. `unknown_entity` counts only an emitted type with no standard census mapping.

A Form 0 Trimmed Surface Entity (Type 144) stores a support-surface pointer, an outer-boundary flag, an inner-boundary count, an outer Curve on a Parametric Surface pointer, and the ordered inner Curve on a Parametric Surface pointers. When the outer-boundary flag is zero, the outer pointer is zero or omitted and the rectangular parameter domain of the support surface supplies the outer boundary. The entity then produces no explicit outer loop; each listed loop is `inner`. When the flag is one, the outer pointer is present and produces the single `outer` loop; each listed loop is `inner`.

## Appearance

Directory color zero supplies no direct color. Positive values `1` through `8` select black, red, green, blue, yellow, magenta, cyan, and white. A negative value is the negated odd Directory sequence of a Form 0 Color Definition Entity (Type 314). Type 314 stores red, green, and blue intensities as finite percentages from `0` through `100` and an optional Hollerith name. Neutral RGBA components equal the percentages divided by `100`, with alpha `1`.

Directory line-font values `1` through `5` select standard patterns. A negative value is the negated odd Directory sequence of a Line Font Definition Entity (Type 304) and resolves to its `iges:presentation:line-font#D{n}` native identity. Form 1 stores an orientation flag, a Form 0 Subfigure Definition pointer, a positive display spacing, and a positive template scale. Form 2 stores a positive segment count, that many positive segment lengths, and exactly `ceil(count / 4)` hexadecimal digits. Pattern bits are right-justified; the unit bit describes the last segment, and unused high bits are zero. Type 304 has entity-use flag `02` and carries a standard fallback line-font value `1` through `5` in its Directory entry.

A nonnegative Directory level value selects that single exchange-file level. A negative value is the negated odd Directory sequence of a Definition Levels Property Entity (Type 406, Form 1). The property stores a positive count followed by that many distinct nonnegative level numbers. A malformed definition or link is retained but does not become a decoded display-level set.

A positive Directory line-weight number selects that numbered increment in the uniform Global line-weight series and cannot exceed the Global maximum gradation count. Its model-space width is `number * maximum_width / maximum_gradations`; neutral/native display width converts that result to millimetres. Zero leaves the display width unspecified.

A Manifold Solid B-rep Object or orphan Shell color binds to its body. A Face color binds to that face and overrides the body color for that face. Trimmed and bounded surface colors bind to their generated sheet body and face. The blank-status field determines body visibility. Curve and surface source-object associations retain their direct Directory colors.

The `native.iges` namespace version is `2`. Its `colors` arena stores typed Type 314 percentages, names, and fallback color numbers. Its `line_fonts` arena stores typed template and visible-blank definitions. Its `definition_levels` arena stores ordered multiple-level sets. Its `display_attributes` arena stores one record per Directory entity with visibility, line-font number or definition link, level number or definition link, view, line weight, and color number or definition link. These values remain distinct from effective neutral appearance bindings.

## Byte accounting

The Fixed ASCII reader retains every physical card and every Directory/Parameter entity in `native.iges`, including typed domain arenas where projected and generic entity records otherwise. Card payloads, line endings, Directory fields, Parameter tokens, links, and source identities remain available through that namespace. `SourceFidelity` retains the complete source image as a byte record and records its document-local SHA-256 digest. The reader does not emit a closed `transfer_ledger`.
