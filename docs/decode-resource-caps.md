# Decode resource-cap classification

Every production `const MAX_*` under `crates/**/src` (excluding
`#[cfg(test)]` modules and `tests/` trees) belongs to one policy kind.
The kinds are mutually exclusive. A constant that both bounds a counted
read and later contributes to session totals is classified by the role of
the named cap, not by later charging at a different site.

`cadmpeg-codec-sat` has no production `MAX_*`. SAT header admission already
charges entities through `DecodeContext`. `cadmpeg-asm` has none.

| Kind | Meaning                     | Enforcement                                                                                                                                                                            |
| ---- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | Format invariant            | Keep. A higher count is an unsupported form. An operator profile must not accept an illegal form or reject a legal file.                                                               |
| 2    | Per-input allocation bound  | `bounded_len`, `View::read_counted`, or `req_take`. Do not add a `ResourceLimits` field.                                                                                               |
| 3    | Cumulative resource ceiling | Charge through `DecodeContext` (`charge_entities`, `admit_entities`, `charge_collection_items`, `charge_retained`, `reserve_scoped`, `alloc_filled`, `enter_nested`).                  |
| 4    | Algorithmic work cap        | `ctx.work_budget(min(format_cap, policy.max_work_units))` / `charge_work`. CATIA `b5` object-stream selection and F3D arrangement walks already do this; do not duplicate those sites. |

The nine `ResourceLimits` fields are `max_input_bytes`,
`max_decompressed_bytes_total`, `max_decompressed_bytes_per_expand`,
`max_materialized_bytes`, `max_retained_bytes`, `max_entities`,
`max_collection_items`, `max_recursion_depth`, and `max_work_units`.
This classification does not add fields.

## Routing

Kind 3 and kind 4 constants take a session charge or a `work_budget`. A
format-side named cap stays as the local slice and is taken as `min` with
the matching `ResourceLimits` field.

- IGES product occurrences charge collection items and use `enter_nested`.
  Output and depth take `min` with `max_collection_items` /
  `max_recursion_depth`. Type-124 chains and composite flattening use
  `enter_nested`.
- STEP parse records, parameters, anchors, and REFERENCE materialization
  charge entities, collection items, work, and retained storage. Nesting
  uses `enter_nested` against `max_recursion_depth`. Occurrence expansion
  uses `admit_entities` and takes `min` with `max_entities` /
  `max_recursion_depth`.
- FreeCAD `Document.xml` object Count uses `admit_entities` and takes
  `min` with `max_entities`. Property value XML charges
  `max_retained_bytes`.
- Rhino mesh zlib buffers use `begin_expand`. Buffer output takes `min`
  with `max_decompressed_bytes_per_expand` and charges
  `max_retained_bytes`. Instance expansion charges
  `max_collection_items` / `max_entities` / `max_recursion_depth`.
- Inventor has only kind 2 constants. SAT has none.
- Rhino `MAX_BREP_DEPTH` and `MAX_CURVE_DEPTH` have no session context at
  the payload layer. They stay named recursion caps.
