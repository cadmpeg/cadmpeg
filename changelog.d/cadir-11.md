### Breaking

- No tool converts a CADIR 10 document to CADIR 11: keep the source CAD files. [Upgrading from CADIR 10](https://github.com/cadmpeg/cadmpeg/blob/main/docs/upgrading-to-cadir-11.md) lists the layout changes and the new arena paths.
- A CADIR 11 document holds its topology under `geometry` and its feature history under `design`: `.model.faces` is `.geometry.faces`, and `.model.features` is `.design.features`. `cadmpeg query` names the arenas the same way. `scope` replaces `decode_depth`.
- Keep the `.fidelity.json` decode sidecar beside its `.cadir.json`. A FreeCAD, SolidWorks, or Fusion write reads it to preserve the source or track edits (FreeCAD and SolidWorks report `export:edit.unverified` without it). On an edited `.cadir.json`, SolidWorks and Fusion restore history arenas from the retained source when the sidecar is present; without it (including a CLI conversion of a hand-edited `.cadir.json`, whose sidecar is ignored with `decode/sidecar.stale`), SolidWorks refuses the write and Fusion regenerates from `design` (`f3d:source.preserved-image-unavailable`).
- `convert` writes the output when the check finds errors, and reports the findings. `--allow-errors` is removed: remove it from scripts. `--reject-errors` refuses the write (exit 1) with `strict_export_rejected`, and `--reject-lossy` refusal codes are `strict_decode_rejected` and `strict_export_rejected`. `measure` on a document with no model class exits 0 with `measure:output.empty` unless `--reject-empty` is passed.
- Writers produce a file and report losses for many documents that they refused before. A script that used the refusal as its signal reads the losses, or passes `--reject-lossy=export`.
- `cadmpeg check` applies the validation rules of the CADIR 11 specification, also to the design and process layers (`check` values `design` and `process`). It can report errors on a decode that an earlier release passed. In `check --json` and every validation report, each finding writes `rule` and `related`; `cadmpeg check` text output and `cadmpeg query findings` also include `rule`.
- Loss codes and severities change for several formats: for example, an unreadable record is `decode/record.unreadable`, and a defective STEP statement is an `Error`. A script that matches loss codes, or `--reject-lossy` with an `Error` floor, can give a different result. The list below names each change.
- The Rust API of the `cadmpeg-*` crates changes, including `CadIr::from_json` refusing out-of-order or repeated arena IDs (use `CadIr::read` for hand-edited documents). The list below names each change.
